## What runs this application?

One Cloudflare Worker. `src/server.ts` is the entry point; TanStack Start handles everything that is not short-circuited before it. Data is in D1, media in R2, the audit log and the newsletter travel through Cloudflare Queues, each with a dead-letter queue, realtime invalidation goes through a Durable Object, and `CACHE`, a KV namespace, holds a few short-lived keys: the e-mail sender flag, incident-alert deduplication and the health probe.

Bun installs packages and runs `package.json` scripts. Vite+ (`vp`) provides the dev server, the build, the formatter, the linter and the test runner, all configured in `vite.config.ts`.

## Which package manager, and which versions?

`packageManager` is `bun@1.4.0`. Use `bun install` and `bun run <script>` so the repository's tool versions are selected. `vp toolchain` prints the versions in the active Vite+ release.

## Do I need a Cloudflare account to develop?

For `bun run dev`, yes. The `development` Wrangler environment uses remote bindings — it talks to the real preview D1 database, the real preview R2 bucket and the real KV namespace. For tests, no: they run against an in-memory `node:sqlite` database behind a D1-shaped transport and read dummy values from the committed `.env.test`. Nor for the end-to-end suite, which runs the local `test` Wrangler environment.

## Which locale is the default?

`pl-PL`. It is served with no prefix, so `/products` is Polish. `en-US` is served under `/en-US`. Both are declared in `src/integrations/use-intl/i18n.config.ts`, along with the `marte_locale` cookie name and `Europe/Warsaw` as the shop's own time zone. A redundant `/pl-PL/...` URL is 301'd to the bare path in the Worker.

## Which time zone and number format does a page use?

The viewer's own, not the page language's. `getDisplayPreferences` in `src/integrations/use-intl/i18n.display-preferences.ts` resolves them on every request, and `TranslationsProvider` passes them to `IntlProvider`. The time zone is the signed-in user's saved choice, else the `marte_time_zone` cookie the browser writes from `Intl.DateTimeFormat().resolvedOptions().timeZone`, else Cloudflare's guess for the request (`request.cf.timezone`), else `UTC`. The format locale, which shapes dates, prices and numbers, is the user's saved choice, else the first supported `Accept-Language` entry, else `en-US`. Users pick both under Preferences on `/account/profile`. `Europe/Warsaw` remains the shop's own zone for order-number years and legal deadlines.

## Where does a new operation go?

If it reads or writes a database table, it is a use case in that table's module: `src/modules/<feature>/use-cases/<verb>-<noun>.ts`. It exports a `createServerFn` server function with its `authorized` middleware, a Zod `validator` and the query or mutation options next to it.

If it is pure data access with no authorization decision, it belongs in that module's `*.accessors.ts` and is called from a use case.

If it touches no table and only one route needs it, define it in that route file. If it is a small request-scoped helper, `src/lib`.

## When do I create a new module?

Only when you add a database table: a folder in `src/modules` exists only for a table of the same name. `_core` is the one folder without a table, and it holds the helpers that several tables share. `storefront-search` owns the `storefront_search` FTS5 virtual table, which its migration creates and `drizzle.schemas.ts` does not export. An operation without a table of its own goes to the module of the table it reads or writes, or to `_core` when it serves several.

## Where does a new component go?

`src/presentation/components/custom`. A component shared across areas is a flat file there; a component belonging to one page or area goes under `components/custom/pages/<area>/`. One widget, dialog, form or column definition per file. shadcn primitives live in `components/shadcn` and are not hand-edited.

## How do I pass text into a component?

You don't. The component calls `useTranslations` for its own namespace and reads the text itself. There are no `label` or `title` props, and no component takes data it could fetch through the owning use case's query options.

## How do I add a translation namespace?

Create `messages/en-US/<namespace>.json` and `messages/pl-PL/<namespace>.json` — both, always — then list the namespace in the route's `staticData.namespaces`. A namespace declared without a file throws `Missing translation namespace: messages/<locale>/<namespace>.json` at load time.

## Why does every server-side request read the session from D1?

Better Auth's cookie cache is turned off, and `getRequestSession` also passes `disableCookieCache: true`, so a banned or signed-out user cannot ride a cached cookie — not even at Better Auth's own endpoints. The cost is one D1 read per HTTP request, not per call: the lookup is memoized per `Request` in a `WeakMap`, so concurrent loaders and server functions in the same request share it.

## Why is authorization inside the use cases rather than on the routes?

Because a server function is a public HTTP endpoint. It can be called directly, without the route that normally calls it ever being loaded, so a `beforeLoad` guard cannot protect it — and guards also run in the browser. The `authorized` middleware runs on the server, before any database access. Route guards exist for navigation only.

A test in `src/integrations/better-auth/__test__/use-case-authorization.test.ts` enforces this: every use case with a `createServerFn` must contain `authorized(` unless it is on the 24-entry public allowlist.

## Why are there no database transactions?

D1 has no interactive transactions. `db.batch()` is atomic, so anything that must be all-or-nothing is built as a list of statements and run through `runDrizzleBatch`. Where a read has to happen before the write, the code uses a guarded `UPDATE` — inventory reservation asks for `quantityAvailable >= quantity` in the statement that takes the stock — plus a unique index that makes the losing branch's `INSERT` fail the whole batch.

## How is money stored?

As integers in the currency's minor unit. `product_variant.price` and `compare_at_price`, and `order.subtotal`, `tax_total`, `shipping_total`, `discount_total` and `total` are all `integer`. `order.currency_code` is a three-character column defaulting to `PLN`. Exponents come from the ISO 4217 table in `src/modules/_core/constants/currency.ts`, so formatting never guesses at two decimal places.

## Where are delivery methods and prices changed?

In the admin, under **Settings → Delivery** (`/admin/settings/delivery`). It adds methods, changes their names in both languages and their prices, hides, archives and restores them, sets the order the checkout lists them in, and sets the free delivery threshold. `delivery_method.price` and `store_setting.free_delivery_threshold` are minor units like every other amount. The seed file, `delivery-methods.sql`, only inserts the rows that are not there yet (`INSERT OR IGNORE`). See [Shipping and delivery](/docs/features/shipping-and-delivery#managing-delivery-methods).

## Where are the shop's legal name, address and NIP changed?

In the admin, under **Settings → Store details** (`/admin/settings/store`): the legal name, street, postal code, city, country, NIP, REGON, contact e-mail and phone. The footer, the about page, product pages, the checkout's pickup step, the e-mails, the structured data and the legal pages read them from the `store_setting` row, so a save shows everywhere without a release. The legal pages name them through placeholders such as `:seller[nip]`, and the two PDF forms are made from them each time they are opened; only the pickup sentences in the terms and the FAQ still need an edit of their own. See [Admin settings](/docs/features/admin-settings#store-details).

## How do I give someone admin access?

The person creates an account in the shop and confirms their e-mail address. Then, under **Settings › Team** (`/admin/settings/team`), **Add admin** finds the account by its address or name and makes it an admin; **Remove access** on its row takes the access away and signs it out everywhere. Nobody can change their own access, so the shop always keeps an admin, and a change needs a sign-in from the last 24 hours. The new admin turns on two-factor authentication before the panel opens. See [Admin settings: Team](/docs/features/admin-settings#team).

## How does a change in one browser tab reach another admin's screen?

Through the `RealtimeInvalidationHub` Durable Object. A mutation calls a `schedule*Invalidation` helper, the Worker invokes `hub.notifyInvalidation(prefixes)` as a native RPC method, and the hub broadcasts to every socket in that audience. Tabs subscribe to a fixed prefix list — 23 for admin, 15 for storefront, 3 for the checkout — and discard messages that do not overlap.

## How do I preview a transactional email?

Run the dev server and open `/dev/emails`. The route is defined in `src/routes/dev.emails.tsx`, and its `GET` handler answers 404 unless `import.meta.env.DEV`. The templates themselves are in `src/presentation/emails/`, and each one reads its own `emails.*` namespace.

## What is scaffolded but not finished?

InPost shipments are booked, labelled and tracked from the admin order page, but InPost's status does not move the order; the admin still marks it shipped and delivered. Without ShipX credentials the order page explains how to ship by hand in InPost Manager and paste the tracking number. `cart` and `cart_item` are registered in the Drizzle schema but unused. `/admin/settings` covers the admin's own account and sign-in security, the seller's details, the shop's delivery methods and free delivery, and the team of admins; the carriers themselves and staff notifications are not in it yet.

## What happens to orders placed as a guest?

They stay guest orders until an account verifies an address they belong to. A guest checkout paid with the address of an already verified account is filed under that account at fulfilment, and an account that verifies its address later takes over, through `claimGuestOrdersForUser` in `src/modules/order/use-cases/claim-guest-orders.server.ts`, the guest orders placed with any of its addresses while it held them and those placed with the verified address while no account held it. An order placed with an address while another account held it stays for that account. Matching ignores case, and each claim is recorded as `customer.orders_claimed`. The `20261016140000_claim_past_guest_orders.sql` migration did the same once for orders placed before this existed.

## How do I run the end-to-end tests?

`bun run test:e2e:install` once, then `bun run test:e2e:pr` for the Chromium projects CI runs or `bun run test:e2e` for all of them. Playwright builds and serves the local `test` Worker itself, with a migrated and seeded database under `.wrangler/test` and Stripe, Resend and InPost ShipX emulated, so no Cloudflare account is needed; stop `bun run dev` first, because a server already on port 3000 is reused. `bun run test:e2e:stripe` pays in Stripe's real Payment Element and needs a Stripe sandbox's test keys. See [Project scripts](/docs/getting-started/project-scripts#end-to-end-tests).

## How are the docs themselves organized?

`content/docs/<folder>/<slug>.<locale>.mdx`, with a `meta.<locale>.json` per folder listing `pages` in reading order and a translated `title`. Both locales must carry the same slugs. The sidebar is built from the **top-level folders** only, so a page must live one level deep to appear. `bun run content` regenerates `.source/`; `bun run dev` runs it for you.

Pages are plain Markdown. The renderer in `src/presentation/components/custom/docs-mdx.tsx` maps HTML elements only, with no component registry, so custom MDX components are not available.

## Which command do I run before pushing?

```sh
bun run check
bun run test
```

`check` is format, lint and type check; CI then adds `test:coverage` and `build:preview`, and a Chromium end-to-end job that `bun run test:e2e:pr` reproduces. The pre-commit hook already runs `vp staged` over changed files, and `prepare-commit-msg` validates the Conventional Commit type and prefixes its emoji.
