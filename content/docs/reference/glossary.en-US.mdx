title: "Glossary"
description: "The vocabulary used across the M'Arte documentation and codebase, with the file that defines each term."
---

Terms are listed alphabetically. Where a term corresponds to a concrete export, the defining file is named.

## Application vocabulary

- **Accessor** — a plain data-access function in `<module>/<module>.accessors.ts`. It takes arguments, talks to `db`, and has no notion of who is asking. Authorization lives one layer up, in the use case.
- **AppError** — the single error class server code throws, from `src/modules/_core/constants/errors.ts`. It carries one of eight `ERROR_CODES` and an optional module-specific reason string.
- **Audit event** — a row in the `audit_log` table, enqueued rather than written inline. Categories are `orders`, `email`, `customers`, `catalog`, `content`, `settings` and `auth`; severities are `info`, `success`, `warning`, `error`; actor roles are `admin`, `customer`, `system`, `unknown`. Defined in `src/modules/audit-log/audit-log.constants.ts`.
- **Binding** — a Cloudflare resource the Worker receives from `env`: `DB` (D1), `CACHE` (KV), `IMAGES` (R2), `AUDIT_LOG_QUEUE` and `NEWSLETTER_QUEUE` (Queue producers), `REALTIME_INVALIDATION_HUB` (Durable Object) and `ASSETS` (static assets).
- **Checkout** — a row in the `checkout` table representing one payment attempt, created before Stripe is contacted and resolved by a webhook. Distinct from the **cart**, which is a Zustand store in `src/hooks/use-cart-store.ts` persisted to `localStorage` as `marte-cart`; the `cart` and `cart_item` tables are declared, but nothing reads or writes them.
- **Collection** — a curated group of products (`product_collection`, joined through `collection_on_product`). Distinct from a **category** (`product_category`), which is hierarchical and has a `parentId`.
- **Compensation** — releasing inventory that was already reserved when a later line in the same cart fails its reservation guard. Best-effort: its own failure is caught and logged.
- **Display preferences** — the time zone and format locale that dates, prices and numbers are shown in, resolved per request by `getDisplayPreferences` in `src/integrations/use-intl/i18n.display-preferences.ts`. Each is the user's saved choice (`user.timezone`, `user.format_locale`), or else detected: the time zone from the `marte_time_zone` cookie the browser writes, then Cloudflare's `request.cf.timezone`, then `UTC`; the format locale from `Accept-Language`, then `en-US`. Users choose them under Preferences on `/account/profile`.
- **Drizzle batch** — a list of statements run atomically on D1 through `runDrizzleBatch` in `src/integrations/drizzle-orm/drizzle.batch.ts`. D1 has no interactive transactions, so a batch is the only atomicity primitive available.
- **Email address history** — the `user_email_history` table: one row per address an account has used, with `added_at` and `replaced_at`, written by two triggers on `user` and read through `src/modules/user-email-history/user-email-history.accessors.ts`. See [Account: The addresses an account has used](/docs/features/account#the-addresses-an-account-has-used).
- **Format locale** — the locale used only to format numbers, prices and dates, one of the 18 `FORMAT_LOCALES` in `src/integrations/use-intl/i18n.display.ts`. Independent of the page language, which is always `pl-PL` or `en-US`. Part of the display preferences.
- **Guard** — a function a layout route passes as its `beforeLoad` to redirect before the route loads: `requireSignedIn`, `requireAdminRole`, `requireAdmin`, `requireCustomer`, `redirectIfSignedIn`, all in `src/integrations/better-auth/auth.routes.ts`. The first four resolve to `{ user }`, which becomes route context. Guards are navigation UX, not authorization.
- **Guest order claim** — filing a guest order under an account: at fulfilment, under the account that has verified the order's e-mail address, and through `claimGuestOrdersForUser` in `src/modules/order/use-cases/claim-guest-orders.server.ts` when an account verifies its address, under the account that held the order's address when the order was placed, or that verifies it when no account held it then. Recorded as `customer.orders_claimed`.
- **Handle** — the URL-safe slug of a product, category or collection. Unique, lower-case, hyphen-separated, validated against a pattern such as `CATEGORY_HANDLE_PATTERN`. Used in place of an id in storefront and admin URLs.
- **Integration** — a folder in `src/integrations` that wraps one third party: `better-auth`, `cloudflare-r2`, `drizzle-orm`, `fumadocs`, `gsap`, `inpost`, `lenis`, `react-day-picker`, `mdxeditor`, `realtime-invalidation`, `resend`, `stripe`, `tanstack-query`, `use-intl`.
- **Layout route** — a route that renders an `Outlet` for its children and usually declares shared `staticData.namespaces`: `_storefront.tsx`, `account.tsx`, `admin.tsx`, `auth.tsx`, `checkout.tsx`, `docs.tsx`.
- **Locale prefix** — the `/<locale>` segment used for every locale except the default. `pl-PL` is the default and collapses to no prefix; `en-US` is served under `/en-US`. Handled by `localizePathname` and `deLocalizePathname` in `src/integrations/use-intl/i18n.paths.ts`.
- **Middleware** — a function that runs before a server function's handler: `withRequest` (error normalisation), `authorized` (session and permission), `withRateLimit` (per-IP budget). All three are in `src/integrations/better-auth/auth.middleware.ts`.
- **Module** — a folder in `src/modules`. Forty own at least one database table; four own no table and group operations instead.
- **Mutation key** — the tuple in a module's `<ENTITY>_MUTATION_KEYS` used to identify a mutation for cache and pending-state purposes, for example `CATEGORY_MUTATION_KEYS.REORDER`.
- **Namespace** — one translation file, named after itself: `pages.admin.catalog.products` is `messages/<locale>/pages.admin.catalog.products.json`. Routes declare the namespaces they need in `staticData.namespaces`.
- **Optimistic concurrency** — the content page save strategy: `updateContentPage` writes only while `updated_at` still equals the value the editor loaded, so a second admin's save is refused instead of overwriting the first. Inventory reservation does not use it: the reserve `UPDATE` is guarded only on `quantityAvailable >= quantity`, and success is signalled by the length of `.returning()`. There is no locking.
- **Order recipient** — the address an order's e-mails go to, `orderRecipientEmail` in `src/modules/order/order.accessors.ts`: the current address of the order's account once that account has replaced the order's address and not returned to it, otherwise `order.email`. See [Orders: Where an order's e-mails go](/docs/features/orders#where-an-orders-e-mails-go).
- **Pathless layout** — a layout route whose file name begins with `_`, so it wraps its children without contributing a URL segment. `_storefront.tsx` is the only one.
- **Price reduction** — a variant whose `compare_at_price` is higher than its `price`. The storefront shows it only when the price is below the lowest price of the 30 days before the reduction, worked out from `price_history`, and then strikes that lowest price through and names it, as Polish law requires (see [Product page](/docs/features/product-page#reduced-prices-and-the-lowest-price-of-the-30-days-before)).
- **Query key** — the tuple identifying a cached query, always taken from a module's `<ENTITY>_QUERY_KEYS`, for example `CATEGORY_QUERY_KEYS.ADMIN.ALL` is `["admin", "categories"]`. Keys are never written inline.
- **Query options** — the `queryOptions` object exported next to a read use case. Loaders, components and invalidation all import the same object, so they cannot drift apart.
- **Realtime hub** — one named instance of the `RealtimeInvalidationHub` Durable Object. There are two audiences, `admin` and `storefront`, declared in `REALTIME_INVALIDATION_HUB`. Admin tabs subscribe to 23 query-key prefixes on the admin hub, storefront tabs to 15 on the storefront hub, and checkout tabs to 3 of those 15, the free delivery threshold, the seller's details and the delivery methods.
- **Root namespaces** — the six translation namespaces preloaded for every route: `common`, `components.custom`, `components.shadcn`, `errors`, `pages.auth.errors`, `pages.auth.toast`. Derived by `ROOT_NAMESPACES` in `src/integrations/use-intl/i18n.messages.ts`.
- **Server function** — a typed RPC operation created with `createServerFn` that always runs on the server and is reachable over HTTP. 138 of them exist under `src/modules/*/use-cases/`.
- **Statement** — one resource-plus-actions entry in the access-control matrix, for example `product: ["create", "read", "update", "delete", "publish"]`. Defined in `PERMISSIONS_STATEMENTS`.
- **Status e-mail** — an e-mail the admin's fulfilment steps send the customer: in progress from `fulfill-order` and delivered from `mark-order-delivered`, each at most once per order, shipped from `announceOrderShipment` once per order, and a tracking e-mail from it once per new tracking number. Templates in `src/presentation/emails/order-in-progress.tsx`, `order-shipped.tsx`, `order-tracking.tsx` and `order-delivered.tsx`.
- **Step back** — moving an order one fulfilment step back — delivered to shipped, shipped to in progress, in progress to confirmed — with `step-back-order` (`order: ["update"]`). It clears that step's timestamp, e-mails nobody and is recorded as `order.stepped_back`; moving forward again sends no second e-mail for a step already announced.
- **Tracking number** — the carrier's parcel number on a shipped order, set when it is shipped or later with `set-order-tracking-number`. `resolveOrderTrackingUrl` in `src/modules/order/order.utils.ts` links it to the stored URL or, for an InPost delivery, to InPost's tracking page.
- **Use case** — one operation in `<module>/use-cases/<verb>-<noun>.ts`. Exports the server function and the query or mutation options that go with it.
- **Variant** — a purchasable configuration of a product (`product_variant`), described by option values through `option_on_variant` and stocked through a one-to-one `inventory` row.
- **Wrangler environment** — one of `development`, `preview`, `test` or `production` in `wrangler.jsonc`, each with its own bindings, `APP_ENV` and `secrets.required` list. `test` binds only local resources and serves the end-to-end suite.

## Infrastructure vocabulary

- **`background`** — `src/lib/background.ts`. `executionContextStorage` is an `AsyncLocalStorage` carrying the Worker's `waitUntil`; `scheduleBackgroundWork(task)` pulls it out at any depth so a promise survives the response. With no store it degrades to a caught fire-and-forget.
- **Cloudflare Queue** — the audit-log and newsletter transport. Audit events are enqueued through `AUDIT_LOG_QUEUE` and consumed by the `queue` export in `src/server.ts`, in batches of up to 50 with a 5-second timeout and 3 retries. Newsletter campaigns are enqueued through `NEWSLETTER_QUEUE` and consumed one message, and so one batch of up to 100 emails, at a time.
- **D1** — Cloudflare's SQLite database, bound as `DB`. No interactive transactions; `db.batch()` is the atomicity primitive.
- **Dead-letter queue** — the `-dlq` queue each queue consumer names as its `dead_letter_queue`. A message that still fails after its retries moves there, and the same Worker consumes it one message at a time with five-minute retries (`retry_delay: 300`). `scripts/verify-bindings.ts` refuses a deploy whose producer queue has none.
- **Durable Object** — `RealtimeInvalidationHub` in `src/durable-objects/realtime-invalidation-hub.ts`, created by the `v1` migration tag. It fans out invalidation messages to connected WebSockets; the storefront hub also keeps the catalogue version of the storefront read cache, the only durable state it holds.
- **KV** — the `CACHE` namespace. Declared in every environment; holds short-lived keys only: the email sender flag that the Better Auth gate reads, the keys that limit incident alerts to one per incident, and the key `/api/health` reads.
- **R2** — the `IMAGES` bucket, holding product media: `martebizuteria` in production, `martebizuteria-preview` in development and preview. Public reads go through the base URL in `VITE_R2_URL`, and a custom domain there gets images resized by Cloudflare Image Transformations.
- **Test Worker** — `martebizuteria-test`, the Worker of the `test` Wrangler environment. Its entry, `src/platform/testing/worker.ts`, installs in-memory emulators for Stripe, Resend and InPost ShipX and adds the `/__test/` endpoints the Playwright specs use to settle Checkout Sessions, then serves the application with local D1, R2 and KV. Built with `bun run build:test`, served with `bun run start:test`, never deployed.
- **Vite+** — the unified toolchain, invoked as `vp`. It provides `vp dev`, `vp build`, `vp check`, `vp fmt`, `vp lint`, `vp test` and `vp staged`, all configured in `vite.config.ts`.

## Tooling vocabulary

- **`.source/`** — the directory Fumadocs MDX generates from `src/integrations/fumadocs/fumadocs.config.ts`. It is aliased as `collections/*` in `tsconfig.json` and regenerated by `bun run content`.
- **Component test** — a `*.component.test.tsx` file, run by the Vitest `component` project in `jsdom` with `src/platform/testing/setup.ts`.
- **End-to-end test** — a Playwright spec in `e2e/specs/`, run against the test Worker by the `chromium`, `webkit`, `*-shop-wide` and `stripe-test-mode` projects of `playwright.config.ts`.
- **Integration test** — a `*.integration.test.ts` file, run by the Vitest `integration` project against an in-memory `node:sqlite` database behind the D1-shaped transport in `src/platform/testing/mocks/d1.ts`.
- **Stripe test mode** — the `stripe-test-mode` Playwright project, which pays by card, BLIK and Przelewy24 in Stripe's real Payment Element against a Stripe sandbox. It runs only when `STRIPE_SECRET_KEY` and `VITE_STRIPE_PUBLISHABLE_KEY` hold sandbox keys, which the **E2E (full)** workflow supplies from `E2E_STRIPE_SECRET_KEY` and `E2E_STRIPE_PUBLISHABLE_KEY`.
- **Unit test** — any other `*.test.ts` or `*.test.tsx` file, run by the Vitest `node` project.
- **`vp check`** — format, lint and type check in one command. The gate CI runs, and the gate the pre-commit hook runs over staged files.
