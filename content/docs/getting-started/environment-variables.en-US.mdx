## The environment files

| File               | Tracked by Git | Loaded by                                                                                                                                                                                                                                                    |
| ------------------ | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `.env.example`     | Yes            | Nothing — it is the template you copy                                                                                                                                                                                                                        |
| `.env.development` | No             | `bun run dev` (Vite mode `development`, `CLOUDFLARE_ENV=development`), `bun run email:verify development`, `scripts/verify-stripe-keys.ts development` and `scripts/verify-turnstile-keys.ts development`                                                    |
| `.env.preview`     | No             | `bun run build:preview`, `bun run start`, `scripts/verify-stripe-keys.ts preview`, `scripts/verify-turnstile-keys.ts preview`, `scripts/verify-email-sender.ts preview` and `scripts/prepare-deploy-secrets.ts preview`; `deploy:preview` runs the last four |
| `.env.production`  | No             | `bun run build:production`, `scripts/verify-stripe-keys.ts production`, `scripts/verify-turnstile-keys.ts production`, `scripts/verify-email-sender.ts production` and `scripts/prepare-deploy-secrets.ts production`; `deploy:production` runs all five     |
| `.env.test`        | Yes            | `vite.config.ts` via `loadEnv("test", …)` for the Vitest projects, and CI builds                                                                                                                                                                             |

`.gitignore` implements exactly that:

```text
.env*
!.env.example
!.env.test
```

Bun's automatic env loading is switched off, so nothing is ever picked up implicitly:

```toml
# bunfig.toml
# Let Vite and Wrangler choose the requested mode. Drizzle scripts opt in with --env-file.
env = false
```

That is why every database script names its file explicitly — `bun --env-file=.env.development run drizzle-kit push …`. Vite loads `.env.<mode>` itself, and Wrangler loads the file matching `CLOUDFLARE_ENV` for local Worker secrets.

Start by copying the template and generating a signing secret:

```sh
cp .env.example .env.development
openssl rand -base64 48
```

Use a different `AUTH_SECRET` per environment. It is the Better Auth signing and encryption secret (`secret: env.AUTH_SECRET` in `src/integrations/better-auth/auth.server.ts`), so rotating it invalidates every session.

## Three kinds of value

The distinction matters more here than the list of names does.

**1. Browser-visible build inputs (`VITE_` prefix).** Vite inlines these into the client bundle at build time. Never put a secret behind a `VITE_` name.

| Variable                      | Read at                                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VITE_STRIPE_PUBLISHABLE_KEY` | `src/integrations/stripe/stripe.client.ts` — `import.meta.env.VITE_STRIPE_PUBLISHABLE_KEY`; `pk_live_` in production and `pk_test_` elsewhere, checked before a deploy by `scripts/verify-stripe-keys.ts`, see [Stripe](/docs/integrations/stripe#secrets)                                                                                                           |
| `VITE_TURNSTILE_SITE_KEY`     | `src/integrations/cloudflare-turnstile/turnstile.client.ts`, the site key of the checkout's bot check; Cloudflare's testing key `1x00000000000000000000AA` outside production and the shop's own widget's key in production, checked before a deploy by `scripts/verify-turnstile-keys.ts`, see [Cloudflare Turnstile](/docs/integrations/cloudflare-turnstile#keys) |
| `VITE_R2_URL`                 | `src/lib/url.ts` — the client branch of `getAssetCdnBase()`                                                                                                                                                                                                                                                                                                          |

**2. Worker secrets.** Declared per environment under `secrets.required` in `wrangler.jsonc` and read on the server with `import { env } from "cloudflare:workers"`. Every environment declares the same eleven:

| Secret                      | Read at                                                                                                                                                                                                                                                                                                                                    |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `AUTH_SECRET`               | `src/integrations/better-auth/auth.server.ts`                                                                                                                                                                                                                                                                                              |
| `AUTH_GOOGLE_CLIENT_ID`     | `socialProviders.google` in `auth.server.ts`                                                                                                                                                                                                                                                                                               |
| `AUTH_GOOGLE_CLIENT_SECRET` | `socialProviders.google` in `auth.server.ts`                                                                                                                                                                                                                                                                                               |
| `INPOST_API_TOKEN`          | `src/integrations/inpost/inpost.shipx.server.ts`, as the ShipX bearer token; may be left blank, which turns InPost shipments off, see [InPost](/docs/integrations/inpost#credentials)                                                                                                                                                      |
| `INPOST_ORGANIZATION_ID`    | `src/integrations/inpost/inpost.shipx.server.ts`, in the ShipX shipment URL and to recognise the webhook; may be left blank like the token                                                                                                                                                                                                 |
| `RESEND_API_KEY`            | `src/integrations/resend/resend.config.ts`; checked before a deploy by `scripts/verify-email-sender.ts`, see [Resend](/docs/integrations/resend#sender-domain)                                                                                                                                                                             |
| `RESEND_EMAIL_FROM`         | `src/integrations/resend/resend.send.ts`, wrapped as `M'Arte <…>`; a bare address on a verified domain whose mailbox someone reads, because the shop's notices and incident alerts go to it in every environment; checked before a deploy by `scripts/verify-email-sender.ts`, see [Resend](/docs/integrations/resend#sender-domain)       |
| `STRIPE_SECRET_KEY`         | `src/integrations/stripe/stripe.server.ts`; `sk_live_` or `rk_live_` in production and a test key elsewhere, checked before a deploy by `scripts/verify-stripe-keys.ts`, see [Stripe](/docs/integrations/stripe#secrets)                                                                                                                   |
| `STRIPE_WEBHOOK_SECRET`     | `src/routes/api/webhooks.stripe.ts`, for signature verification                                                                                                                                                                                                                                                                            |
| `TURNSTILE_SECRET_KEY`      | `src/integrations/cloudflare-turnstile/turnstile.server.ts`, sent to Turnstile's siteverify with every checkout's token; the testing key `1x0000000000000000000000000000000AA` outside production, checked before a deploy by `scripts/verify-turnstile-keys.ts`, see [Cloudflare Turnstile](/docs/integrations/cloudflare-turnstile#keys) |
| `VITE_R2_URL`               | `src/lib/url.ts` — the server branch of `getAssetCdnBase()`                                                                                                                                                                                                                                                                                |

`VITE_R2_URL` is deliberately in both lists. It is not a secret; it is the public R2 base URL, and both the SSR render and the browser need it, so it is uploaded as a Worker binding _and_ inlined into the client bundle. Each environment points it at its own bucket: the `r2.dev` address of `martebizuteria-preview` in `.env.development` and `.env.preview`, and the custom domain `https://images.martebizuteria.pl` in `.env.production`, where images are resized through Cloudflare Image Transformations. [Image delivery](/docs/guides/image-delivery) sets them up.

**3. Local tooling credentials.** These are never uploaded. `scripts/prepare-deploy-secrets.ts` copies only the names under `secrets.required`, and its comment says why:

```ts
// Only declared Worker bindings are uploaded; Cloudflare management tokens stay local.
```

| Variable                    | Used by                                                                                                                                                                                                    |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CLOUDFLARE_ACCOUNT_ID`     | `src/integrations/drizzle-orm/drizzle.config.ts`, D1 HTTP driver                                                                                                                                           |
| `CLOUDFLARE_DATABASE_ID`    | The same — which database `db:push`, `db:studio` and `db:introspect` target                                                                                                                                |
| `CLOUDFLARE_ACCESS_TOKEN`   | The same, as the API token                                                                                                                                                                                 |
| `RESEND_MANAGEMENT_API_KEY` | `scripts/verify-email-sender.ts`, optional: a Resend Full access key that reads the sender domain's DNS records when `RESEND_API_KEY` may only send, see [Resend](/docs/integrations/resend#sender-domain) |

The three `CLOUDFLARE_*` values are read through `process.env` in the Drizzle config and default to `""`, so a missing value surfaces as an authentication failure from the D1 HTTP API rather than a clear error.

## Plain vars, not secrets

`wrangler.jsonc` also sets one plain variable per environment:

```jsonc
"vars": {
  "APP_ENV": "preview",
},
```

`APP_ENV` is read in `src/server.ts` to decide what `robots.txt` says, and `scripts/verify-build.ts` asserts that the built Worker's `APP_ENV` matches the environment you asked for. That is the guard that stops a preview build being deployed to production.

## Values that live in code, not in the environment

Several settings people expect to find in `.env` are constants:

| What                                                                         | Where                                                   |
| ---------------------------------------------------------------------------- | ------------------------------------------------------- |
| `APP_NAME`, `APP_DOMAIN`, `APP_URL`, OG image, theme colour, R2 fallback URL | `src/presentation/branding/app.ts`                      |
| Legal name, NIP, REGON, address, phone, opening hours                        | `src/presentation/branding/business.ts`                 |
| Facebook and Instagram links                                                 | `src/presentation/branding/socials.ts`                  |
| Hosts each mode serves: auth, email links, the Stripe return URL             | `HOSTS_BY_MODE` in `src/modules/_core/constants/api.ts` |
| Supported locales, default locale, locale cookie name, timezones             | `src/integrations/use-intl/i18n.config.ts`              |
| D1, R2, KV and Queue identifiers, Worker names, custom domains               | `wrangler.jsonc`                                        |

`appHostsForMode` is the one to remember when you change domains:

```ts
export const WORKERS_DEV_HOSTS = {
  preview: "martebizuteria-preview.pjborowiecki.workers.dev",
  production: "martebizuteria.pjborowiecki.workers.dev",
} as const

const HOSTS_BY_MODE: Readonly<Record<string, readonly string[]>> = {
  preview: [`preview.${APP_DOMAIN}`, WORKERS_DEV_HOSTS.preview],
  production: [APP_DOMAIN, WORKERS_DEV_HOSTS.production],
}

const LOCAL_HOSTS = ["localhost:3000", "127.0.0.1:3000"]
```

Better Auth is configured with `baseURL: { allowedHosts: appHostsForMode(import.meta.env.MODE) }`. A host missing from this list will have its auth requests rejected, which looks like sign-in silently failing on a new domain. `WORKERS_DEV_HOSTS` is also where the deploy's live-site check sends its requests, so a Worker renamed in `wrangler.jsonc` needs its new `workers.dev` name there. Every other host of a deployed mode is attached to that Worker as a custom domain by `routes` in `wrangler.jsonc`, so a new domain goes into both files, and `src/modules/_core/constants/__test__/api.test.ts` fails until they agree.

`resolveRequestOrigin` (`src/lib/request.ts`) checks the same list before the app builds a link into an email or a Stripe `return_url`, so emails link back to the host the customer or admin used: `localhost:3000` or `127.0.0.1:3000` locally, the preview host on preview, and `martebizuteria.pl` or the production `workers.dev` name in production. A request on a host missing from the list is refused with `FORBIDDEN`. The order confirmation is sent from the Stripe webhook and takes the origin of the session's `return_url`, which `resolveDeploymentOrigin` checks against the hosts of every mode. `LOCAL_HOSTS` pins port 3000, which Vite's `strictPort` already enforces for the dev server.

## Provider callbacks to register

| Provider | URL                                       | Verified with                                                     |
| -------- | ----------------------------------------- | ----------------------------------------------------------------- |
| Google   | `https://<host>/api/auth/callback/google` | Client id and secret                                              |
| Stripe   | `https://<host>/api/webhooks/stripe`      | `STRIPE_WEBHOOK_SECRET`                                           |
| InPost   | `https://<host>/api/webhooks/inpost`      | Not verified; the route reads each named shipment back from ShipX |

On a deployed Worker, `<host>` is its `workers.dev` name, or on preview its custom domain `preview.martebizuteria.pl`; production gets `martebizuteria.pl` when the shop goes live. The auth handler is `src/routes/api/auth.$.ts`, mounted at `/api/auth/$`; the Stripe handler is `src/routes/api/webhooks.stripe.ts` and accepts `POST` only. The InPost handler is `src/routes/api/webhooks.inpost.ts`; it answers `GET` with 200 for InPost Manager's address check and acts on a `POST`, up to 120 a minute from one address. The host the Stripe endpoint is registered on does not change any email: the order confirmation links to the address the checkout was made on, which the session's `return_url` carries.

## Declared but not wired

Two names exist in the repository without a matching consumer. They are listed here so you do not spend time hunting for the code that reads them:

| Name                    | Where it appears                                                             | Status                                                                                                                                                      |
| ----------------------- | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VITE_APP_URL`          | `env:` in `.github/workflows/deploy-preview.yml` and `deploy-production.yml` | Not in `.env.example`, not a declared secret, and not read anywhere in `src/`. The canonical URL comes from `APP_URL` in `src/presentation/branding/app.ts` |
| `VITE_IMAGE_CDN_DOMAIN` | Read in `src/lib/image.ts` by `resolveImageCdnDomain()`                      | Absent from `.env.example`. When unset it falls back to the hostname of `APP_URL`, which is the normal case                                                 |
