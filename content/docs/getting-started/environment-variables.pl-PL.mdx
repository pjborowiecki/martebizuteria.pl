## Pliki środowiskowe

| Plik               | Wersjonowany w Git | Wczytywany przez                                                                                                                                                                                                                                                                                                              |
| ------------------ | ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.env.example`     | Tak                | Nic — to szablon do skopiowania                                                                                                                                                                                                                                                                                               |
| `.env.development` | Nie                | `bun run dev` (tryb Vite `development`, `CLOUDFLARE_ENV=development`), `bun run email:verify development` oraz `scripts/verify-stripe-keys.ts development`                                                                                                                                                                    |
| `.env.preview`     | Nie                | `bun run build:preview`, `bun run start`, `scripts/verify-stripe-keys.ts preview`, `scripts/verify-email-sender.ts preview` oraz `scripts/prepare-deploy-secrets.ts preview`; `deploy:preview` uruchamia wszystkie poza `start`                                                                                               |
| `.env.production`  | Nie                | `bun run build:production`, `scripts/verify-stripe-keys.ts production`, `scripts/verify-email-sender.ts production` oraz `scripts/prepare-deploy-secrets.ts production`; wszystkie cztery uruchamia `deploy:production`                                                                                                       |
| `.env.test`        | Tak                | `vite.config.ts` przez `loadEnv("test", …)` dla projektów Vitest; `bun run build:test` (tryb Vite `test`) dla Workera testów end-to-end; `scripts/seed-test.ts`, który jego `AUTH_SECRET` szyfruje sekret dwuskładnikowy administratora z danych startowych; oraz CI, które kopiuje go na `.env.development` i `.env.preview` |

`.gitignore` realizuje dokładnie ten podział:

```text
.env*
!.env.example
!.env.test
```

Automatyczne wczytywanie zmiennych przez Buna jest wyłączone, więc nic nie jest nigdy pobierane w sposób niejawny:

```toml
# bunfig.toml
# Let Vite and Wrangler choose the requested mode. Drizzle scripts opt in with --env-file.
env = false
```

Dlatego każdy skrypt bazodanowy jawnie wskazuje swój plik — `bun --env-file=.env.development run drizzle-kit push …`. Vite sam wczytuje `.env.<mode>`, a Wrangler wczytuje plik odpowiadający zmiennej `CLOUDFLARE_ENV`, aby udostępnić lokalne sekrety Workera.

Zacznij od skopiowania szablonu i wygenerowania sekretu podpisu:

```sh
cp .env.example .env.development
openssl rand -base64 48
```

Użyj innej wartości `AUTH_SECRET` dla każdego środowiska. To sekret Better Auth do podpisywania i szyfrowania (`secret: env.AUTH_SECRET` w `src/integrations/better-auth/auth.server.ts`), więc jego rotacja unieważnia wszystkie sesje.

## Trzy rodzaje wartości

Ten podział jest tu ważniejszy niż sama lista nazw.

**1. Wejścia buildu widoczne w przeglądarce (prefiks `VITE_`).** Vite wstawia je do bundle'a klienckiego na etapie budowania. Nigdy nie umieszczaj sekretu pod nazwą z prefiksem `VITE_`.

| Zmienna                       | Odczytywana w                                                                                                                                                                                                                                                    |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VITE_STRIPE_PUBLISHABLE_KEY` | `src/integrations/stripe/stripe.client.ts` — `import.meta.env.VITE_STRIPE_PUBLISHABLE_KEY`; `pk_live_` na produkcji i `pk_test_` gdzie indziej, przed wdrożeniem sprawdza go `scripts/verify-stripe-keys.ts`, zobacz [Stripe](/docs/integrations/stripe#sekrety) |
| `VITE_R2_URL`                 | `src/lib/url.ts` — gałąź klienta w `getAssetCdnBase()`                                                                                                                                                                                                           |

**2. Sekrety Workera.** Deklarowane osobno dla każdego środowiska w sekcji `secrets.required` w `wrangler.jsonc` i odczytywane na serwerze przez `import { env } from "cloudflare:workers"`. Każde środowisko deklaruje te same dziesięć:

| Sekret                      | Odczytywany w                                                                                                                                                                                                                                                                                                                                          |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `AUTH_SECRET`               | `src/integrations/better-auth/auth.server.ts`                                                                                                                                                                                                                                                                                                          |
| `AUTH_GOOGLE_CLIENT_ID`     | `socialProviders.google` w `auth.server.ts`                                                                                                                                                                                                                                                                                                            |
| `AUTH_GOOGLE_CLIENT_SECRET` | `socialProviders.google` w `auth.server.ts`                                                                                                                                                                                                                                                                                                            |
| `INPOST_API_TOKEN`          | `src/integrations/inpost/inpost.shipx.server.ts`, jako token ShipX; może zostać pusty, co wyłącza przesyłki InPost, zobacz [InPost](/docs/integrations/inpost#dane-dostępowe)                                                                                                                                                                          |
| `INPOST_ORGANIZATION_ID`    | `src/integrations/inpost/inpost.shipx.server.ts`, w adresie tworzenia przesyłki ShipX i do rozpoznania webhooka; może zostać pusty jak token                                                                                                                                                                                                           |
| `RESEND_API_KEY`            | `src/integrations/resend/resend.config.ts`; przed wdrożeniem sprawdza go `scripts/verify-email-sender.ts`, zobacz [Resend](/docs/integrations/resend#domena-nadawcy)                                                                                                                                                                                   |
| `RESEND_EMAIL_FROM`         | `src/integrations/resend/resend.send.ts`, opakowany jako `M'Arte <…>`; sam adres w zweryfikowanej domenie, którego skrzynkę ktoś czyta, bo w każdym środowisku trafiają na niego powiadomienia sklepu i alerty o incydentach; przed wdrożeniem sprawdza go `scripts/verify-email-sender.ts`, zobacz [Resend](/docs/integrations/resend#domena-nadawcy) |
| `STRIPE_SECRET_KEY`         | `src/integrations/stripe/stripe.server.ts`; `sk_live_` albo `rk_live_` na produkcji i klucz testowy gdzie indziej, przed wdrożeniem sprawdza go `scripts/verify-stripe-keys.ts`, zobacz [Stripe](/docs/integrations/stripe#sekrety)                                                                                                                    |
| `STRIPE_WEBHOOK_SECRET`     | `src/routes/api/webhooks.stripe.ts`, do weryfikacji podpisu                                                                                                                                                                                                                                                                                            |
| `VITE_R2_URL`               | `src/lib/url.ts` — gałąź serwera w `getAssetCdnBase()`                                                                                                                                                                                                                                                                                                 |

`VITE_R2_URL` celowo występuje na obu listach. To nie sekret, a publiczny adres bazowy R2 — potrzebują go zarówno render SSR, jak i przeglądarka, więc jest wysyłany jako binding Workera _i_ wstawiany do bundle'a klienckiego. Każde środowisko kieruje go na własny bucket: adres `r2.dev` bucketu `martebizuteria-preview` w `.env.development` i `.env.preview`, a własną domenę `https://images.martebizuteria.pl` w `.env.production`, gdzie zdjęcia zmniejszane są przez Cloudflare Image Transformations. Konfigurację opisuje [Dostarczanie zdjęć](/docs/guides/image-delivery).

**3. Dane uwierzytelniające lokalnych narzędzi.** Te nigdy nie są wysyłane. `scripts/prepare-deploy-secrets.ts` kopiuje wyłącznie nazwy z `secrets.required`, a jego komentarz wyjaśnia dlaczego:

```ts
// Only declared Worker bindings are uploaded; Cloudflare management tokens stay local.
```

| Zmienna                     | Używana przez                                                                                                                                                                                                                              |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `CLOUDFLARE_ACCOUNT_ID`     | `src/integrations/drizzle-orm/drizzle.config.ts`, sterownik HTTP D1                                                                                                                                                                        |
| `CLOUDFLARE_DATABASE_ID`    | To samo — wskazuje bazę, na której działają `db:push`, `db:studio` i `db:introspect`                                                                                                                                                       |
| `CLOUDFLARE_ACCESS_TOKEN`   | To samo, jako token API                                                                                                                                                                                                                    |
| `RESEND_MANAGEMENT_API_KEY` | `scripts/verify-email-sender.ts`, opcjonalny: klucz Resend z pełnym dostępem (Full access), który odczytuje rekordy DNS domeny nadawcy, gdy `RESEND_API_KEY` może tylko wysyłać; zobacz [Resend](/docs/integrations/resend#domena-nadawcy) |

Trzy wartości `CLOUDFLARE_*` są odczytywane przez `process.env` w konfiguracji Drizzle i domyślnie przyjmują `""`, więc brakująca wartość objawia się błędem uwierzytelnienia z API HTTP D1, a nie czytelnym komunikatem.

## Zwykłe zmienne, nie sekrety

`wrangler.jsonc` ustawia też jedną zwykłą zmienną na środowisko:

```jsonc
"vars": {
  "APP_ENV": "preview",
},
```

`APP_ENV` przyjmuje wartość `development`, `preview`, `test` albo `production`, a serwer czyta go wszędzie tam, gdzie zachowanie zależy od środowiska:

| Gdzie                                                                                                       | O czym decyduje `APP_ENV`                                                                                                                                                                                             |
| ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/server.ts`, `generateRobotsTxt` w `src/lib/seo.ts`                                                     | Tylko `production` wpuszcza roboty przez `robots.txt`                                                                                                                                                                 |
| `withSecurityHeaders` w `src/lib/security-headers.ts`                                                       | `Strict-Transport-Security` jest wysyłany przez HTTPS wszędzie poza `development` i `test`                                                                                                                            |
| `src/routes/api/webhooks.stripe.ts`                                                                         | `production` przyjmuje tylko zdarzenia Stripe w trybie live, a każde inne środowisko tylko testowe (`requiredStripeMode`)                                                                                             |
| `src/integrations/stripe/stripe.deployment.ts`                                                              | Metadane `deployment` nadawane każdej sesji Checkout (`martebizuteria-preview` dla developmentu i preview, `martebizuteria-test`, `martebizuteria`) oraz sprawdzenie, które pomija testowe zdarzenia innego wdrożenia |
| `src/integrations/inpost/inpost.shipx.server.ts`                                                            | `production` nadaje prawdziwe paczki przez ShipX; każde inne środowisko korzysta z piaskownicy InPost                                                                                                                 |
| `resend.availability.server.ts`, `resend.public-email-limits.server.ts`, `src/lib/incident-alert.server.ts` | Prefiks ich kluczy KV i limitów, dzięki czemu development i preview, które dzielą KV i D1, mają osobne flagi nadawcy, limity e-maili i deduplikację alertów; alert o incydencie podaje też nazwę środowiska           |

`scripts/verify-build.ts` sprawdza, czy zbudowany Worker ma `APP_ENV` zgodny z żądanym środowiskiem. To właśnie ten warunek nie pozwala wdrożyć buildu preview na produkcję.

## Wartości, które żyją w kodzie, a nie w środowisku

Kilka ustawień, których ludzie szukają w `.env`, jest stałymi:

| Co                                                                                                                  | Gdzie                                                                                                     |
| ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `APP_NAME`, `APP_DOMAIN`, `APP_URL`, obrazek OG, kolor motywu, zapasowy URL R2                                      | `src/presentation/branding/app.ts`                                                                        |
| Nazwa firmy, NIP, REGON, adres, e-mail kontaktowy, telefon                                                          | Nie w kodzie: wiersz `store_setting` w D1, zmieniany w Ustawienia → Dane sklepu (`/admin/settings/store`) |
| Godziny otwarcia punktu odbioru                                                                                     | `deliverySubsteps.inStoreText` w `messages/*/pages.checkout.json` oraz regulamin i FAQ w `/admin/content` |
| Linki do Facebooka i Instagrama                                                                                     | `src/presentation/branding/socials.ts`                                                                    |
| Hosty obsługiwane w każdym trybie: logowanie, linki w e-mailach, powrót ze Stripe                                   | `HOSTS_BY_MODE` w `src/modules/_core/constants/api.ts`                                                    |
| Obsługiwane lokalizacje, lokalizacja domyślna, nazwa ciasteczka, strefa czasowa sklepu `Europe/Warsaw`              | `src/integrations/use-intl/i18n.config.ts`                                                                |
| Strefy czasowe do wyboru przez użytkownika (`TIMEZONES`)                                                            | `src/modules/_core/constants/timezone.ts`                                                                 |
| Formaty regionalne do wyboru (`FORMAT_LOCALES`), ciasteczko `marte_time_zone` i wykrywanie preferencji wyświetlania | `src/integrations/use-intl/i18n.display.ts`                                                               |
| Identyfikatory D1, R2, KV i kolejki, nazwy Workerów, domeny własne                                                  | `wrangler.jsonc`                                                                                          |

O `appHostsForMode` trzeba pamiętać przy każdej zmianie domeny:

```ts
export const WORKERS_DEV_HOSTS = {
  preview: "martebizuteria-preview.pjborowiecki.workers.dev",
  production: "martebizuteria.pjborowiecki.workers.dev",
} as const

const HOSTS_BY_MODE: Readonly<Record<string, readonly string[]>> = {
  preview: [`preview.${APP_DOMAIN}`, WORKERS_DEV_HOSTS.preview],
  production: [APP_DOMAIN, WORKERS_DEV_HOSTS.production],
}

const LOCAL_HOSTS = ["localhost:3000", "127.0.0.1:3000"]
```

Better Auth jest skonfigurowany z `baseURL: { allowedHosts: appHostsForMode(import.meta.env.MODE) }`. Host, którego nie ma na tej liście, będzie miał odrzucane żądania uwierzytelniania — wygląda to jak ciche niedziałanie logowania na nowej domenie. Pod `WORKERS_DEV_HOSTS` wysyła też swoje żądania kontrola działającej strony na końcu wdrożenia, więc Worker przemianowany w `wrangler.jsonc` potrzebuje tam swojej nowej nazwy `workers.dev`. Drugi host preview, `preview.martebizuteria.pl`, jest podłączony do Workera preview jako domena własna przez `routes` w `wrangler.jsonc`, więc nowa domena preview trafia do obu plików, a `src/modules/_core/constants/__test__/api.test.ts` nie przechodzi, dopóki się nie zgadzają. Produkcja ma `routes: []` aż do startu sprzedaży, co sprawdza ten sam test, więc na razie działa wyłącznie pod nazwą `workers.dev`, choć `martebizuteria.pl` jest już na jej liście hostów.

Tę samą listę sprawdza `resolveRequestOrigin` (`src/lib/request.ts`), zanim aplikacja zbuduje link do e-maila albo `return_url` dla Stripe, więc e-maile linkują do hosta, którego używał klient albo administrator: lokalnie do `localhost:3000` albo `127.0.0.1:3000`, na preview do hosta preview, a na produkcji do `martebizuteria.pl` albo produkcyjnej nazwy `workers.dev`. Żądanie na host spoza listy jest odrzucane z `FORBIDDEN`. Potwierdzenie zamówienia wysyła webhook Stripe i bierze ono origin z `return_url` sesji, który `resolveDeploymentOrigin` sprawdza z hostami wszystkich trybów. `LOCAL_HOSTS` przypina port 3000, co dla serwera deweloperskiego i tak wymusza `strictPort` w Vite.

## Adresy zwrotne do zarejestrowania

| Dostawca | URL                                                                  | Weryfikowany przez                                                      |
| -------- | -------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Google   | `https://<host>/api/auth/callback/google`                            | Identyfikator i sekret klienta                                          |
| Stripe   | `https://<host>/api/webhooks/stripe`, wersja API `2026-09-30.endive` | `STRIPE_WEBHOOK_SECRET`                                                 |
| InPost   | `https://<host>/api/webhooks/inpost`                                 | Nie jest weryfikowany; trasa odczytuje każdą wskazaną przesyłkę z ShipX |

Na wdrożonym Workerze `<host>` to jego nazwa `workers.dev`, a na preview także domena własna `preview.martebizuteria.pl`; produkcja dostanie `martebizuteria.pl` przy starcie sprzedaży. Handler uwierzytelniania to `src/routes/api/auth.$.ts`, zamontowany pod `/api/auth/$`; handler Stripe to `src/routes/api/webhooks.stripe.ts` i przyjmuje wyłącznie `POST`. Handler InPost to `src/routes/api/webhooks.inpost.ts`; na `GET` odpowiada 200 dla sprawdzenia adresu w Managerze Paczek, a działa na `POST`, do 120 na minutę z jednego adresu. Host, na którym zarejestrowano punkt końcowy Stripe, nie zmienia żadnego e-maila: potwierdzenie zamówienia linkuje pod adres, na którym złożono zamówienie, a ten adres niesie `return_url` sesji.

## Zadeklarowane, ale niepodłączone

Dwie nazwy istnieją w repozytorium bez kodu, który je odczytuje. Wymieniamy je tutaj, żebyś nie tracił czasu na szukanie:

| Nazwa                   | Gdzie występuje                                                                  | Stan                                                                                                                                                                        |
| ----------------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VITE_APP_URL`          | Sekcja `env:` w `.github/workflows/deploy-preview.yml` i `deploy-production.yml` | Brak w `.env.example`, nie jest zadeklarowanym sekretem i nie jest odczytywany nigdzie w `src/`. Kanoniczny adres pochodzi z `APP_URL` w `src/presentation/branding/app.ts` |
| `VITE_IMAGE_CDN_DOMAIN` | Odczytywany w `src/lib/image.ts` przez `resolveImageCdnDomain()`                 | Brak w `.env.example`. Gdy nie jest ustawiony, używana jest nazwa hosta z `APP_URL` — i tak jest w normalnej sytuacji                                                       |
