M'Arte ma jeden menedżer pakietów i jeden zestaw narzędzi. Bun (`bun@1.4.0`, przypięty w polu `packageManager` w `package.json`) instaluje zależności i uruchamia skrypty; Vite+ (`vp`) obsługuje serwer deweloperski, kompilacje, testy, linter, formater i kontrole plików w przechowalni Gita; Wrangler rozmawia z Cloudflare; drizzle-kit generuje migracje i otwiera Drizzle Studio. Wszystko, czego te narzędzia potrzebują, znajduje się w trzech plikach w katalogu głównym repozytorium: `package.json`, `vite.config.ts` i `wrangler.jsonc`.

Nie ma tu osobnych wywołań ESLinta, Prettiera, Jesta czy `tsc`. `bun run check` to jedyna bramka statyczna — formatowanie, lint i kontrola typów — a `bun run test` to jedyne wejście do testów.

## Stos w skrócie

| Narzędzie   | Wersja                 | Skąd pochodzi                 | Do czego służy                                                          |
| ----------- | ---------------------- | ----------------------------- | ----------------------------------------------------------------------- |
| Bun         | `1.4.0`                | `packageManager`              | Instalacja, uruchamianie skryptów, `Bun.Transpiler` w `verify-build.ts` |
| Vite+       | `1.1.0`                | `devDependencies.vite-plus`   | `vp dev`, `vp build`, `vp test`, `vp check`, `vp staged`                |
| Vitest      | `5.0.3`                | `overrides.vitest`            | Runner testów pod `vp test`                                             |
| TypeScript  | `~7.0.2`               | `devDependencies.typescript`  | Typy, sprawdzane przez Vite+, a nie osobnym wywołaniem `tsc`            |
| Wrangler    | `^4.149.0`             | `devDependencies.wrangler`    | Migracje D1, wdrożenia, typy bindingów                                  |
| drizzle-kit | `^0.31.11`             | `devDependencies.drizzle-kit` | Generowanie migracji, introspekcja, Studio                              |
| Fumadocs    | `fumadocs-mdx@^15.4.7` | `dependencies`                | Kompiluje `content/` do `.source/`                                      |

`package.json` przestawia także samo Vite: `overrides.vite` wskazuje na `npm:@voidzero-dev/vite-plus-core@1.1.0`, więc Vite, które projekt rozwiązuje, jest tym dostarczanym przez Vite+.

## Czego tutaj nie ma

Domyślny zestaw testów przeglądarkowych nigdy nie wywołuje Stripe'a. Rozlicza płatności przez emulator w testowym Workerze, więc sam formularz płatności Stripe'a, z obsługą karty, 3D Secure, BLIK-a i Przelewy24, działa tylko w osobnym projekcie `stripe-test-mode`, który potrzebuje kluczy sandboxa Stripe'a. CI ma je w sekretach repozytorium, więc zadanie `stripe-test-mode` w `e2e-full.yml` płaci przez sandbox Stripe'a przy każdym uruchomieniu tego przepływu: po każdym pushu do `main`, w poniedziałki o 03:15 UTC i przy uruchomieniu ręcznym. Lokalnie projekt pomija swoje specyfikacje, dopóki klucze nie są ustawione; zobacz [Testy](/docs/tooling/testing#tryb-testowy-stripe).

CI nigdy nie migruje wdrożonej bazy. Każde zadanie end-to-end nakłada całą historię migracji wyłącznie na własną lokalną bazę testową, przez `bun run db:reset:test`; wdrożone bazy migrują skrypty wdrożeniowe, tuż przed `wrangler deploy`, a produkcja wdraża tylko commit, który przeszedł CI. Zobacz [CI/CD](/docs/tooling/ci-cd) i [Wycofanie wdrożenia](/docs/guides/roll-back-a-deploy).

## Pierwsze uruchomienie

```sh
bun install
bun run dev
```

`bun install` wywołuje dwa skrypty cyklu życia: `prepare` (`vp config --no-agent`, który instaluje dyspozytor hooków Gita) oraz `postinstall` (`bun run typegen`, który odtwarza `src/types/worker-configuration.d.ts` i `.source/`). Oba wyniki są w `.gitignore`, więc świeży klon nie przejdzie kontroli typów, dopóki nie powstaną.

`bun run dev` odtwarza kolekcje dokumentacji i startuje Vite+ w środowisku Cloudflare `development` na http://localhost:3000. To środowisko korzysta z **zdalnych** bindingów, więc serwer deweloperski czyta i zapisuje prawdziwą bazę D1 preview, przestrzeń KV i zasobnik R2 (`martebizuteria-preview`).
