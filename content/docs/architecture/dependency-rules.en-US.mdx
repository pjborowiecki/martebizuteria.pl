## Import directions

| Folder                       | May import                                                                                                                                                                                                                | Must not import                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `src/routes`                 | presentation, module query and mutation options, route guards, i18n, Fumadocs, `src/data`, `src/lib`, shared hooks, the two providers (in `__root.tsx`), the realtime hub names and query prefixes, `stripe.constants.ts` | `db`, or any provider client outside a server function or a server route handler |
| `src/presentation`           | module query options, Zod schemas, constants, types, pure utils and client stores, hooks, `src/data`, `src/lib`, the `ROUTES` table, browser-safe integrations                                                            | `drizzle.database.ts`, `auth.server.ts`, `stripe.server.ts`, Resend              |
| `src/modules/*/use-cases`    | integrations (`db`, `authorized`, `sendEmail`, Stripe, R2), `_core`, module accessors and schemas, email templates, `src/presentation/branding`                                                                           | components                                                                       |
| `src/modules/*.accessors.ts` | `db`, `drizzle.utils.ts` and `drizzle.batch.ts`, module schemas, constants, types and utils, other modules' accessors, `_core` utils                                                                                      | route guards, components, other modules' use cases                               |
| `src/integrations`           | `_core`, module schemas, constants, accessors, `*.server.ts` helpers and the use cases a vendor calls back into, `src/presentation/branding`                                                                              | components, except the one `fumadocs.docs.ts` loads lazily                       |
| `src/server.ts`              | the Start handler, `resolveLocale`, the realtime WebSocket handler, the newsletter and audit-log queue consumers, `src/lib`                                                                                               | the database, Better Auth or the Stripe SDK directly                             |

Two kinds of import run from modules and integrations into presentation. `_core/constants/api.ts`, `auth.server.ts`, `stripe.server.ts`, `resend.send.ts` and `resend.sender.ts` read the shop name or domain from `src/presentation/branding/app.ts`. Six module constants files (`discount`, `newsletter-subscriber`, `product-attribute`, `product-category`, `product-collection` and `user`) take `CATALOG_ADMIN_RECORD_ID_COLUMN_WIDTH_PX` from `src/presentation/components/custom/pages/admin/catalog/lib/catalog-admin-datagrid.constants.ts` for the record-id column of their admin grids. The component exception is `loadDocsPage` in `fumadocs.docs.ts`, which dynamically imports `custom/docs-content.tsx` to preload the compiled page before rendering it.

Browser-safe integrations are the ones with no `env` read and no server-only marker. Client code imports these directly: `i18n.config.ts`, `i18n.paths.ts`, `i18n.utils.ts`, `i18n.display.ts`, `i18n.messages.ts`, `auth.client.ts`, `auth.access.ts`, `auth.errors.ts`, `auth.zod.ts`, `auth.constraints.ts`, `auth.routes.ts`, `stripe.client.ts`, `stripe.appearance.ts`, `stripe.checkout.ts`, `stripe.checkout.processing.ts`, `stripe.constants.ts`, `stripe.errors.ts`, `stripe.utils.ts`, `inpost.constants.ts`, `inpost.queries.ts`, `inpost.utils.ts`, `inpost.zod.ts`, `media.zod.ts`, `gsap.loader.ts`, `lenis.instance.ts`, `lenis.scroll.ts`, `mdxeditor.plugins.ts`, `react-day-picker.locale.ts`, `realtime-invalidation.protocol.ts`, `realtime-invalidation.subscriptions.ts`, `query.invalidation.ts` and `query.sync.ts`. Components also import `auth.session.ts`, `i18n.display-preferences.ts`, `media.mutations.ts` and `fumadocs.docs.ts` for the server functions and query options they export; the handlers in those files are compiled out of the client bundle. `gsap.config.ts` is browser-safe too. `gsap.loader.ts` reaches it through a dynamic `import()`, and only `use-landing-animations.ts` and `use-product-animations.ts` import it statically, so GSAP is in the route code of the home page, `/categories` and the product page and out of every other page's JavaScript; see [GSAP and Lenis](/docs/integrations/gsap-and-lenis).

## Server-only boundaries

- **Server functions.** TanStack Start compiles every `createServerFn` handler out of the browser bundle and replaces the call with an RPC request. That is why `src/hooks/use-wishlist.ts` and `wishlist-grid.tsx` can import `toggleWishlistItemMutation` from `toggle-wishlist-item.ts`, which also imports `db`.
- **Import protection.** TanStack Start's import protection runs with its defaults (`vite.config.ts` does not configure it). In the client environment it denies files named `*.server.*`, files that import the `@tanstack/react-start/server-only` marker, and `@tanstack/react-start/server`. A denied import that survives the server-function compilation fails `vp build`; in `vp dev` it is replaced by a mock that logs an error when used. Imports that only a compiled-out handler used are not violations.
- **Server-only marker.** Seven files start with `import "@tanstack/react-start/server-only"`: `drizzle.database.ts`, `src/lib/rate-limit.ts`, `src/lib/background.ts`, `src/lib/retention.ts`, `src/lib/server-timing.ts`, `src/lib/sitemap.ts` and `src/lib/request.ts`. Other files that read bindings or secrets carry no marker: most are named `*.server.ts` (`auth.server.ts`, `stripe.server.ts`), `resend.config.ts` and `resend.send.ts` are imported only by `*.server.ts` files, and `media.mutations.ts` reads `env` only inside its server function handler.
- **The `.server.ts` suffix** marks module and integration files that are only ever reached from a server function, a server route or the Worker entry — `find-settled-order.server.ts`, `find-pending-checkout.server.ts`, `schedule-audit-log.server.ts`, `save-complete-product.server.ts` and the rest. The suffix tells readers where the file runs, and it is also the file pattern import protection denies in the client.
- **Environment-specific functions.** `createServerOnlyFn` wraps code that only runs on the server (`getRequestSession`). `createIsomorphicFn` provides separate implementations per environment (`getCurrentLocale`, `getCurrentPathname` in `i18n.utils.ts`, `getAssetCdnBase` in `src/lib/url.ts`). `createClientOnlyFn` wraps calls that only run in the browser, such as the Better Auth client requests in the auth forms.
- **Bindings and secrets** come from `env` in `cloudflare:workers`. It is read in server-only code: the integration clients and `*.server.ts` files, server function files such as `media.mutations.ts`, the server handlers of `src/routes/api/health.ts`, `webhooks.stripe.ts` and `webhooks.inpost.ts`, and the Durable Object. `src/lib/url.ts` reads it only in the `.server()` branch of `getAssetCdnBase`; the `.client()` branch reads `import.meta.env.VITE_R2_URL`. `src/server.ts` receives `env` as a `fetch` argument and passes it on in the request context.

```ts
import "@tanstack/react-start/server-only"

import { env } from "cloudflare:workers"

import { drizzle } from "drizzle-orm/d1"

import * as schema from "~/src/integrations/drizzle-orm/drizzle.schemas"

import { timeD1Statements } from "~/src/lib/server-timing"

const instrumentedBinding = (): D1Database => timeD1Statements(env.DB)

class DeferredD1Database implements D1Database {
  prepare = (query: string): D1PreparedStatement => instrumentedBinding().prepare(query)
  // batch, exec and withSession forward the same way; dump rejects
}

export const db = drizzle(new DeferredD1Database(), { schema })
```

`bun run build:preview` and `bun run build:production` end with `bun scripts/verify-build.ts <environment>`, which fails the build if the client bundle still carries an unbundled `cloudflare:workers` or `node:*` import, or Drizzle ORM. That script is the mechanical check behind these rules.

## The import order is a layer diagram

`vite.config.ts` defines 17 custom import groups under `fmt.sortImports`, and the formatter applies them. Reading the groups top to bottom is reading the dependency direction:

```text
server-only → cloudflare → react → builtin/external → platform → providers →
integrations → modules → routes → hooks → constants → types → lib → branding →
components-shadcn → components-custom → components-other → styles → relative
```

`bun run format` (or `bun run check:fix`) rewrites the import block into that order, and `bun run check` fails while it is out of order, so a file whose imports look wrong is usually a file in the wrong layer.

## Aliases

`tsconfig.json` maps two prefixes:

| Prefix          | Resolves to   | Used for                                                |
| --------------- | ------------- | ------------------------------------------------------- |
| `~/*`           | `./*`         | Every internal import, always from the repository root  |
| `collections/*` | `./.source/*` | The Fumadocs collections generated by `bun run content` |

Hand-written application code in `src` imports only through `~/`. Relative paths remain in generated files (`src/routeTree.gen.ts`, `src/types/worker-configuration.d.ts`, and the drizzle-kit `schema.ts` and `relations.ts` in `src/integrations/drizzle-orm/migrations`), in the `import.meta.glob` patterns of `src/integrations/use-intl/i18n.messages.ts`, `src/platform/testing/lib/messages.ts` and `src/platform/testing/mocks/migrations.ts`, which Vite resolves relative to the file, and in about 80 test files that import sibling fixtures or their subject relatively. `src/integrations/fumadocs/fumadocs.config.ts`, which `fumadocs-mdx` loads before the alias is available, imports only packages.
