## Trasa

`src/routes/_storefront.products.$handle.tsx`. Loader robi cztery rzeczy:

```ts
loader: async ({ context, params }) => {
  const { locale } = context
  const [data, messages, seller] = await Promise.all([
    context.queryClient.query({ ...getProductQuery(params.handle, locale), staleTime: "static" }),
    context.queryClient.query(messagesQueryOptions<typeof productMessages>({ locale, namespace: "pages.product" })),
    context.queryClient.query(getSellerDetailsQuery()),
  ])

  if (data === false) {
    throw notFound()
  }
  prefetchSingleProductImage(data, context.imagePrefetchService)
  const deferredRelated = defer(context.queryClient.query(getRelatedProductsQuery(data.categoryId, data.id, locale)))

  return {
    deferredRelated,
    description: data.description,
    image: resolveProductSocialImageUrl(data),
    structuredData: buildProductStructuredData({
      images: resolveProductImageUrls(data),
      locale,
      product: data,
      section: messages.heroSection.breadcrumbProducts,
      seller,
    }),
    title: messages.metaTitle.replace("{title}", data.title),
  }
}
```

Zapytanie o produkty powiązane jest **odroczone**: sekcja hero renderuje się natychmiast po rozwiązaniu produktu, a `<Await promise={deferredRelated}>` strumieniuje siatkę powiązanych za nią, z fallbackiem `Suspense` pokazującym `pages.product.loadingRelated`.

`head: pageHead` z `src/lib/seo.ts` zamienia zwrócone `PageMeta` w znaczniki tytułu i opisu, główne zdjęcie produktu w rozmiarze karty społecznościowej 1200 × 630 w `og:image` i `twitter:image` oraz JSON-LD `Product` ze sprzedawcą z Ustawienia → Dane sklepu, którego loader czyta przez `getSellerDetailsQuery()`, jako producentem, tak jak podaje go sekcja „Producent” strony, z jedną `Offer` w PLN na wariant, dostępną albo wyprzedaną według dostępnej ilości, i okruszkami strona główna › produkty › produkt. [Internacjonalizacja](/docs/features/internationalization#seo) wymienia dane strukturalne każdej strony.

## Wczytanie produktu

`getProduct` (`src/modules/product/use-cases/get-product.ts`) jest publiczne:

```ts
const prod = await getPublishedProductByHandleQuery.execute({ handle })

if (prod === undefined || !isProductInStock(prod.variants)) {
  return false
}

return attachPriceReductions(mapPublishedProductForStorefront(prod, locale), await getPriceReductions(prod.variants))
```

Zwróć uwagę na typ zwracany. **Brak produktu i brak stanu magazynowego to oba `false`**, a trasa zamienia `false` w `notFound()`. Nie ma osobnej strony „wyprzedane”: produkt, którego wszystkie warianty mają zero dostępnych sztuk, jest w witrynie błędem 404. `isProductInStock` leży w `src/modules/inventory/inventory.utils.ts`.

`getPublishedProductByHandleQuery` to przygotowane relacyjne zapytanie Drizzle w `product.accessors.ts`, które wczytuje produkt z wariantami, zdjęciami, opcjami i ich wartościami, kategoriami, kolekcjami oraz wartościami atrybutów w jednym przebiegu. `getPriceReductions` dokłada drugi odczyt tylko wtedy, gdy któryś wariant jest przeceniony (zobacz [Obniżone ceny](#obniżone-ceny-i-najniższa-cena-z-30-dni-przed-obniżką)).

## Kształt danych dla witryny

`mapPublishedProductForStorefront` w `src/modules/product/product.utils.ts` spłaszcza wiersz do `Product["storefront"]`. Reguły warte zapamiętania:

| Pole                                       | Jak jest wyznaczane                                                                                   |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| `title`, `subtitle`, `description`, `tags` | `resolveProductTitle` / `Subtitle` / `Description` / `Tags` wybierają język z mapy lokalizacji w JSON |
| `categoryId`                               | `product.primary_category_id`, a gdy kolumna jest `null` — `resolvePrimaryCategoryId(categoryRows)`   |
| `sharedImageUrls`                          | zdjęcia z `variant_id IS NULL` (`isProductLevelImage`)                                                |
| `variants[].imageUrls`                     | własne zdjęcia wariantu, z fallbackiem na `sharedImageUrls`                                           |
| `variants[].specifications`                | wartości atrybutów wariantu, z fallbackiem na wartości na poziomie produktu                           |
| `imageUrls`                                | zdjęcia pierwszego wariantu, potem `sharedImageUrls`, a na końcu wszystkie wiersze zdjęć              |
| `hasVariants`                              | `inferHasVariants(options, variants.length)`                                                          |
| `options`                                  | `{ id, title, values: [{ id, label }] }` z etykietami rozwiązanymi dla języka                         |
| `variants[].optionValueIds`                | `resolveVariantOptionValueIds` — `Record<optionId, valueId>` zbudowany z `option_on_variant`          |
| `variants[].priceReduction`                | `attachPriceReductions` — `{ lowestPrice }` dla wariantu, który pokazuje obniżkę, inaczej `undefined` |

## Wybór wariantu

`use-selected-product-variant.ts` trzyma wybór jako `Record<optionId, valueId>`:

- Początkowy wybór pochodzi z pierwszego wariantu, który ma `quantityAvailable >= 1`, z fallbackiem na `variants[0]`.
- `selectOptionValue(optionId, valueId)` wylicza kolejny wybór i **zatwierdza go tylko wtedy, gdy istnieje pasujący wariant**, więc selektor nie może trafić w nieistniejącą kombinację.
- `selectedVariant` jest `undefined` wyłącznie wtedy, gdy produkt w ogóle nie ma wariantów.

`product-variant-picker.tsx` renderuje grupy opcji; `product-hero-gallery.tsx` podmienia zdjęcia przy zmianie wariantu, bo `ProductHeroSection` przelicza `images` z `selectedVariant?.imageUrls`. Poniżej `lg` zdjęcia tworzą zapętloną karuzelę z przyciskami poprzedniego i następnego zdjęcia oraz kropką dla każdego zdjęcia. Przyciski noszą nazwy „Poprzednie zdjęcie” i „Następne zdjęcie”, a kropki „Zdjęcie 1”, „Zdjęcie 2” i tak dalej, z `pages.product.heroSection.gallery` (po angielsku „Previous image”, „Next image”, „Image 1”), więc czytnik ekranu odczytuje każdy element w języku klienta.

Galeria renderuje każde zdjęcie dwa razy, raz w karuzeli na telefonie (`lg:hidden`) i raz w kolumnie na komputerze (`hidden lg:block`). Pierwsze zdjęcie jest Largest Contentful Paint strony w obu punktach przerwania, więc obie jego kopie dostają `priority`, a każde inne zdjęcie jest leniwe przy domyślnym priorytecie. Wszystkie kopie mają wspólne `sizes`, `(width < 64rem) 100vw, 58vw`, to samo źródło i te same wymiary, więc przy każdej szerokości okna przeglądarka sprowadza obie kopie pierwszego zdjęcia do jednego adresu: renderowanie Reacta na serwerze wysyła jeden preload obrazu, a kopia ukryta w danym punkcie przerwania nie kosztuje drugiego pobrania.

## Dodanie do koszyka

`use-product-hero-cart.ts` to jedyne miejsce, w którym karta produktu zapisuje do koszyka. Uwzględnia stan magazynowy:

- `availableQuantity = getVariantQuantityAvailable(selectedVariant)`
- `isOutOfStock` to `availableQuantity < 1`
- `canPurchase = isVariantPurchasable(selectedVariant, quantity)`
- jeśli wybrana ilość przekracza dostępną, efekt ją obniża
- wybór ilości zatrzymuje się na mniejszej z wartości: `availableQuantity` albo `CART_LINE_QUANTITY_MAX`, czyli najwyższej liczbie sztuk jednego produktu w zamówieniu
- zmiana wariantu resetuje ilość do 1

Po kliknięciu wpycha jedną linię do store'a zustand i wysyła zdarzenie aktywności:

```ts
addItem({
  id: selectedVariant.id,
  image: getProductImageUrl(heroImage),
  price,
  qty: addQuantity,
  rawPrice: variantPrice,
  slug: product.handle,
  title: product.title,
  variantId: selectedVariant.id,
  variantTitle,
})
trackCartItemAdded({ productTitle: product.title, quantity: addQuantity, variantId: selectedVariant.id, variantTitle })
```

`price` to już sformatowany napis, a `rawPrice` to jednostki podrzędne; koszyk preferuje `rawPrice` i tylko awaryjnie parsuje `price`. `variantTitle` jest czyszczone, gdy równa się `DEFAULT_VARIANT_TITLE` (`product-variant.utils.ts`), żeby produkty jednowariantowe nie pokazywały bezsensownej etykiety wariantu. `isAdded` przechodzi w `true` na 2000 ms, co napędza stan potwierdzenia na przycisku.

Śledzenie przechodzi przez `src/presentation/components/custom/customer-activity-tracking.ts` i jest zapisywane wyłącznie dla zalogowanych użytkowników. Zobacz [Dziennik zdarzeń](/docs/features/audit-log).

## Wyświetlanie ceny

`product-hero-info.tsx` formatuje `price` wybranego wariantu przez `useFormatter().number(centsToDisplayAmount(variantPrice), { currency: "PLN", style: "currency" })`. Gdy żaden wariant nie jest wybrany, pokazuje `EMPTY_VALUE` z `src/modules/_core/constants/placeholder.ts`. Waluta jest tu zapisana wprost jako `"PLN"`, a nie odczytana ze `STORE_CURRENCY_CODE`. Cenę i `priceReduction` wybranego wariantu przekazuje do `ProductPrice`, który dokłada obniżkę opisaną niżej.

## Obniżone ceny i najniższa cena z 30 dni przed obniżką

Wariant jest przeceniony, gdy ma ustawione `compare_at_price` wyższe niż `price`; tak właściciel wystawia go na wyprzedaż. Polskie prawo (art. 4 ust. 2 i 3 ustawy o informowaniu o cenach towarów i usług, który wdraża art. 6a unijnej dyrektywy w sprawie podawania cen w brzmieniu nadanym dyrektywą Omnibus) wymaga, by obok każdej obniżonej ceny stała najniższa cena z 30 dni przed obniżką, a Trybunał Sprawiedliwości orzekł w sprawie C-330/23 Aldi Süd, że ogłaszaną obniżkę mierzy się od tej najniższej ceny. Dlatego witryna pokazuje obniżkę tylko wtedy, gdy cena jest niższa od najniższej ceny z 30 dni przed obniżką, i przekreśla tę najniższą cenę, a nie cenę regularną.

`price_history` (`src/modules/price-history/`) przechowuje każdą cenę, jaką miał wariant: jeden wiersz na każdą zmianę jego `price` albo `compare_at_price`, z chwilą wejścia zmiany w życie w `changed_at` i całkowitym `id` w kolejności zapisu wierszy. Wiersze zapisują dwa wyzwalacze na `product_variant`, tworzone przez `20261010410000_price_history.sql`. `price_history_variant_insert` zapisuje ceny nowego wariantu, a `price_history_variant_update` zapisuje zmianę którejkolwiek z cen i nic, gdy aktualizacja zostawia obie bez zmian. Wyzwalacz działa wewnątrz instrukcji, która zmieniła wariant, więc wsad zapisu edytora produktu w panelu zapisuje zmiany cen razem z zapisem, a nieudany zapis nie zapisuje żadnej; ceny wpisane przez skrypty wypełniające albo bezpośrednio w D1 są zapisywane tak samo. Migracja zaczyna historię od obecnych cen każdego wariantu z chwili jego `updated_at`. Usunięcie wariantu usuwa jego historię.

`getPriceReductions(variants)` w `price-history.accessors.ts` czyta historię przecenionych wariantów jedną instrukcją, przez `price_history_variantId_idx`, a gdy żaden nie jest przeceniony, nie czyta nic. Następnie `findPriceReduction` w `price-history.utils.ts` rozstrzyga obniżkę każdego wariantu:

- Obniżka zaczęła się od pierwszego z ostatniego ciągu wpisów, które mają obecną cenę wariantu i są przecenione. Zmiana samej ceny regularnej w trakcie obniżki zachowuje ten dzień; kolejne obniżenie ceny zaczyna nową obniżkę.
- Najniższa cena to najniższa z cen obowiązujących w dowolnej chwili 30 dni przed tym dniem (`LOWEST_PRICE_LOOKBACK_MS`), łącznie z ceną, która obowiązywała, gdy te 30 dni się zaczęło.
- Wariant pokazuje obniżkę tylko wtedy, gdy ta najniższa cena jest wyższa od jego obecnej ceny. Cena regularna dodana bez obniżenia ceny, cena, która w tych 30 dniach była przez jakiś czas niższa, i cena podniesiona, która pozostała poniżej ceny regularnej, nie pokazują obniżki.
- Wariant, którego pierwsza zapisana cena jest już obniżona, nie pokazuje obniżki, bo nic nie wskazuje, że kiedyś kosztował więcej. Dotyczy to każdego wariantu, który miał już cenę regularną, gdy migracja zaczęła jego historię.
- Wariant, którego ostatni wpis nie pokazuje ceny, za którą jest sprzedawany, nie pokazuje obniżki.

Najniższa cena należy do dnia obniżki, więc nie zmienia się, dopóki obniżka trwa. `attachPriceReductions`, a dla list `withPriceReductions`, zapisują ją w każdym wariancie jako `priceReduction: { lowestPrice }` albo `undefined`, gdy wariant nie pokazuje obniżki.

`ProductPrice` (`src/presentation/components/custom/product-price.tsx`) pokazuje cenę, przekreśloną najniższą cenę z 30 dni przed obniżką (ukrytą przed czytnikami ekranu, które słyszą tę samą kwotę w wierszu poniżej), a pod nimi `components.custom.productPrice.lowestPriceBeforeReduction`: `Najniższa cena z 30 dni przed obniżką: {price}` po polsku i `Lowest price in the 30 days before the reduction: {price}` po angielsku. Strona produktu pokazuje ją dla wybranego wariantu, a każda karta produktu dla wariantu, który oferuje (zobacz [Katalog i wyszukiwanie](/docs/features/catalog-and-search#obniżone-ceny-na-kartach)). Sama cena regularna nigdy nie pojawia się w witrynie, a JSON-LD `Product` podaje w ofercie każdego wariantu cenę, za którą jest sprzedawany, nigdy cenę regularną ani najniższą wcześniejszą. Koszyk, checkout, lista życzeń i rekomendacje na koncie nie pokazują obniżki, więc nie pokazują też najniższej ceny. Edytor produktu w panelu nie ma jeszcze pola ceny regularnej: obniżkę ustawia się w D1 w `product_variant.compare_at_price`, a edytor przy zapisie zachowuje wczytaną cenę regularną.

## Specyfikacje i szczegóły

`product-hero-details.tsx` renderuje szczegóły jako akordeon: opis i listę specyfikacji, gdy produkt je ma, a potem „Dodatkowe informacje” i „Producent” przy każdym produkcie; pierwsza sekcja jest otwarta. `product-hero-detail-line.ts` eksportuje `resolveProductHeroDetailLine(subtitle, specifications, locale)`, które składa jedną linię podsumowania pod tytułem — z podtytułu, a gdy go brak, ze specyfikacji.

Specyfikacje pochodzą z systemu atrybutów produktu: wiersze `attribute_on_product` mapowane przez `mapAttributeRowsToSpecifications`. Sposób definiowania atrybutów opisuje [Panel katalogu](/docs/features/admin-catalog).

Sekcja „Producent” podaje to, czego unijne rozporządzenie w sprawie ogólnego bezpieczeństwa produktów (art. 19 rozporządzenia (UE) 2023/988) wymaga w ofercie internetowej: nazwę producenta, jego adres pocztowy i adres elektroniczny. Sklep sam wykonuje swoją biżuterię, więc sekcja pokazuje sprzedawcę zapisanego w Ustawienia → Dane sklepu, odczytanego przez `getSellerDetailsQuery()`: nazwę firmy, adres pocztowy i kraj, nazwany w języku kupującego na podstawie zapisanego kodu, oraz e-mail kontaktowy jako odnośnik `mailto:`. Komunikatami w `pages.product.heroSection.details.manufacturer` są tylko etykiety. „Dodatkowe informacje” zawierają zaproszenie do napisania w sprawie innego rozmiaru albo ponownego złocenia, `additionalInfo.flexibleOffer.text`, które linkuje ten sam zapisany e-mail przez `<emailLink>{email}</emailLink>`. Sekcja nie podaje własnych ostrzeżeń: wskazówki pielęgnacyjne albo ostrzeżenia dołączone do danego wyrobu należą do jego specyfikacji jako atrybut produktu. Zobacz [Strony prawne](/docs/features/legal-pages#producent-na-kartach-produktu).

## Pasek zakupu na mobile

`product-mobile-buy-bar.tsx` to przypięty pasek dolny. `ProductHeroInfo` pokazuje go przez `IntersectionObserver` na wierszu zakupu, zabezpieczony przez `matchMedia("(max-width: 1023px)")` — pojawia się więc tylko na małych ekranach i tylko wtedy, gdy prawdziwy wiersz dodania do koszyka wyjechał poza widok.

## Produkty powiązane

`getRelatedProducts` przyjmuje `{ categoryId, excludeProductId, locale }` i zwraca `[]`, gdy `categoryId` jest `null` albo `undefined`. W przeciwnym razie `getPublishedRelatedProducts` w `product.accessors.ts` wybiera w podzapytaniu pozostałe produkty tej samej kategorii:

```ts
.where(and(eq(categoryOnProduct.categoryId, categoryId), ne(categoryOnProduct.productId, excludeProductId)))
```

Przekazuje je do tego samego odczytu listy witryny co nowości na stronie głównej, który trzyma je za bramką `publishedInStockWhere`, porządkuje według `rank`, a przy równym `rank` od najnowszych, i zwraca do `RELATED_PRODUCTS_LIMIT = 3` produktów razem z wariantami jedną instrukcją D1, a drugą po historię cen, gdy któryś z tych wariantów jest przeceniony.

Trasa mapuje wiersze na kształt wymagany przez `ProductRelatedSection`, rozwiązując tytuły dla języka i biorąc `id`, `price`, `priceReduction` i `title` pierwszego wariantu.

## Animacja

`hooks/use-product-animations.ts` jest wywoływany z korzeniem strony i `dependencies: [handle]`, więc animacje odsłaniania odtwarzają się ponownie przy przejściu z jednego produktu na drugi. Ukrywa i odsłania tylko elementy `.reveal` zaczynające się poniżej pierwszego ekranu, takie jak powiązane produkty; okruszki, galeria i panel zakupu są na ekranie od wczytania strony i zostają dokładnie takie, jak namalował je serwer, więc główne zdjęcie jest Largest Contentful Paint od pierwszej klatki. Przy `prefers-reduced-motion: reduce` niczego nie ukrywa ani nie przesuwa.
