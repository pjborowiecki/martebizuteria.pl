Cztery trasy witryny współdzielą jeden komponent katalogu. `/products` to listing bez zawężenia; `/categories/$handle` i `/collections/$handle` to ten sam listing z ustalonym zakresem; `/categories` i `/collections` to siatki indeksowe.

## Trasy

| Trasa                  | Plik                                             | Co renderuje                                             |
| ---------------------- | ------------------------------------------------ | -------------------------------------------------------- |
| `/products`            | `src/routes/_storefront.products.index.tsx`      | `ProductsCatalogPage` bez zakresu                        |
| `/categories`          | `src/routes/_storefront.categories.index.tsx`    | `CategoriesIndexGrid`                                    |
| `/categories/$handle`  | `src/routes/_storefront.categories.$handle.tsx`  | `ProductsCatalogPage` zawężony do `{ categoryHandle }`   |
| `/collections`         | `src/routes/_storefront.collections.index.tsx`   | siatka indeksowa kolekcji                                |
| `/collections/$handle` | `src/routes/_storefront.collections.$handle.tsx` | `ProductsCatalogPage` zawężony do `{ collectionHandle }` |

Same ścieżki pochodzą ze stałych `ROUTES.PRODUCTS`, `ROUTES.CATEGORIES`, `ROUTES.CATEGORY`, `ROUTES.COLLECTIONS` i `ROUTES.COLLECTION` w `src/routes.ts`.

## Stan filtrów żyje w adresie URL

`src/modules/product/product.storefront-catalog.ts` jest właścicielem kontraktu parametrów wyszukiwania. To jedyne miejsce, które trzeba zmienić przy dodaniu filtra.

```ts
export const storefrontProductsSearchSchema = z.object({
  category: z.string().trim().nonempty().optional(),
  collection: z.string().trim().nonempty().optional(),
  maxPrice: z.coerce.number().nonnegative().optional(),
  minPrice: z.coerce.number().nonnegative().optional(),
  q: z.string().trim().nonempty().optional(),
  sort: z.enum(STOREFRONT_PRODUCTS_SORTS).optional(),
})
```

Strony zawężone używają schematów pochodnych, które usuwają parametr ustalony już przez trasę: `storefrontScopedCategoryCatalogSearchSchema` pomija `category`, a `storefrontScopedCollectionCatalogSearchSchema` pomija `collection`.

Cztery wartości sortowania to `rank` (domyślna), `newest`, `price_asc` i `price_desc`.

Obok schematu moduł eksportuje pomocniki używane przez strony:

| Pomocnik                                 | Do czego służy                                                              |
| ---------------------------------------- | --------------------------------------------------------------------------- |
| `normalizeStorefrontProductsSearch`      | usuwa klucze `undefined`, żeby klucz zapytania był stabilny                 |
| `buildEffectiveStorefrontProductsSearch` | scala zakres trasy z parametrami wyszukiwania                               |
| `applyStorefrontProductsSearchPatch`     | nakłada jedną zmianę filtra albo czyści wszystko przez `{ clearAll: true }` |
| `countActiveStorefrontProductFilters`    | zasila licznik filtrów; `sort: "rank"` się nie liczy                        |
| `storefrontCatalogFilterOptions`         | każe licznikowi pominąć parametr ustalony przez zakres                      |

Każda trasa przekazuje funkcję `handleSearchChange`, która nawiguje z `replace: true`, więc filtrowanie nie zapycha historii przeglądarki.

## Zapytanie listingu

`getStorefrontProductsPage` (`src/modules/product/use-cases/get-storefront-products-page.ts`) to publiczna funkcja serwerowa `GET` z middleware `withRequest`. Udostępniana jest jako zapytanie **nieskończone** przez `getStorefrontProductsPageQuery(search, scope)`.

Rozmiar strony zależy od tego, czy jakikolwiek filtr jest aktywny; stałe leżą w `product.constants.ts`:

| Sytuacja      | Rozmiar strony                              | Stronicowanie                                          |
| ------------- | ------------------------------------------- | ------------------------------------------------------ |
| bez filtrów   | `PRODUCT_STOREFRONT_CATALOG_PAGE_SIZE` (12) | `getNextPageParam` idzie dalej, więc siatka doładowuje |
| dowolny filtr | `PRODUCT_STOREFRONT_FILTERED_MAX` (100)     | `getNextPageParam` zwraca `undefined` — jedna strona   |

Przed odpytaniem tabeli produktów handler rozwiązuje handle zakresu na identyfikatory:

- `resolveStorefrontCategoryIdsForSearch` wczytuje jednocześnie kategorię po handle i hierarchię kategorii, a potem wywołuje `collectDescendantCategoryIds(category.id, hierarchy)` z `product-category.utils.ts` — **filtr kategorii obejmuje więc całe jej poddrzewo**.
- `resolveStorefrontCollectionIdForSearch` rozwiązuje handle kolekcji na jeden identyfikator.
- Handle, który nie wskazuje żadnej aktywnej kategorii ani kolekcji, ustawia `unknownScope`, a handler zwraca pustą stronę (`total: 0`), niczego nie listując. Nieznana kolekcja nigdy nie zamienia się w cały katalog.
- `minPrice` i `maxPrice` przychodzą w złotych i są mnożone przez 100 na jednostki podrzędne.

`catalogDebugLog` (`src/lib/catalog-debug-log.ts`) śledzi zdarzenia `storefrontProductsPage.start`, `.unknownScope` i `.done` wraz z czasem w milisekundach.

## Zapytanie SQL

Instrukcję buduje `src/modules/product/product.storefront-catalog.accessors.ts`. Dwie rzeczy warto znać.

**Listowane są wyłącznie produkty opublikowane i dostępne.** `publishedInStockWhere` w `src/modules/product/product.stock.server.ts` to wspólna bramka:

```ts
export const publishedInStockWhere = (...extraConditions: (SQL | undefined)[]): SQL => {
  const conditions = [eq(product.status, PRODUCT_STATUS.PUBLISHED), sql`(${totalStockSubquery()}) > ${0}`, ...extraConditions].filter(
    (condition): condition is SQL => condition !== undefined,
  )

  return and(...conditions)!
}
```

`totalStockSubquery()` sumuje `inventory.quantity_available` po wariantach produktu. Opublikowany produkt, którego wszystkie warianty mają zero, znika z `/products`, ze stron kategorii i kolekcji, z wyszukiwania oraz z karty produktu.

**Złączenie ze statystykami wariantów jest warunkowe.** `productVariantStatsSubquery()` grupuje `product_variant` złączone z `inventory` po `product_id` i udostępnia `min_price`, `total_stock` oraz `variant_count`. Jest dołączane tylko wtedy, gdy w grze jest filtr ceny albo sortowanie po cenie (`storefrontProductsNeedsVariantStatsJoin`), a porządkowanie po cenie używa `coalesce(min_price, 0)`. Domyślna kolejność to `rank` rosnąco, a potem `createdAt` malejąco.

Filtry zakresu to `inArray(product.id, <podzapytanie>)` na tabelach `category_on_product` i `collection_on_product`.

## Fraza wyszukiwania produktu

Parametr `q` przeszukuje indeks FTS5 `storefront_search` przez `storefrontProductMatches(term)` w `src/modules/storefront-search/storefront-search.accessors.server.ts`. `buildStorefrontSearchExpression` zamienia `ł` na `l`, dzieli frazę na słowa i z każdego słowa robi zapytanie o prefiks, więc `zlo pier` znajduje „Złoty pierścionek”. Fraza bez liter i cyfr nie daje niczego do szukania, a strona wraca pusta.

Produkt pasuje, gdy spełnia którykolwiek z tych warunków:

- indeks dopasowuje jego własny tytuł, podtytuł, tagi, opis albo handle;
- należy do aktywnej kategorii lub aktywnej kolekcji, której tekst pasuje do frazy;
- jeden z jego wariantów ma dokładnie taki SKU, bez względu na wielkość liter. `product_variant_upperSku_idx` indeksuje `upper(sku)`, więc SKU wyszukuje się w indeksie, zamiast czytać wszystkie warianty. Dodaje go migracja `20261004120000_product_variant_sku_indexes.sql`, która usuwa też `product_variant_sku_idx`, bo powielał unikalny indeks na `sku`.

`storefrontProductMatches` zbiera te produkty w jednym kroku: wyrażeniu tabelarycznym `storefront_product_matches`. Łączy wyniki czterech źródeł przez `union all` i grupuje je po produkcie, więc każdy produkt pojawia się raz, z trafnością `bm25` własnego tekstu albo z `null`, gdy dotarła do niego tylko kategoria, kolekcja lub SKU. Zliczenie i strona wyników zaczynają się od `with` tego kroku i zostawiają tylko produkty, których identyfikator występuje w dopasowaniach (`in`). Przy domyślnym sortowaniu `rank` strona dołącza jeszcze dopasowania przez `left join` i porządkuje po `coalesce(score, 0)`, potem po `rank` i `createdAt`. Sortowania `newest`, `price_asc` i `price_desc` mają pierwszeństwo przed trafnością, więc przy nich strona w ogóle nie dołącza dopasowań. SQLite materializuje ten krok raz na instrukcję, więc każda instrukcja przeszukuje indeks raz dla każdego rodzaju wpisu, niezależnie od liczby produktów w sklepie. `src/integrations/drizzle-orm/__test__/query-plans.integration.test.ts` zawodzi, gdy plan znów przeszukuje indeks wewnątrz pętli po produktach, gdy sortowanie pomijające trafność dołącza dopasowania albo gdy wyszukiwanie po SKU przestaje korzystać ze swojego indeksu.

## Komponenty

`src/presentation/components/custom/pages/products-catalog/`:

| Plik                                  | Rola                                                                          |
| ------------------------------------- | ----------------------------------------------------------------------------- |
| `products-catalog-page.tsx`           | składa nagłówek, filtry i siatkę; czyta zapytanie nieskończone                |
| `products-catalog-filters.tsx`        | panel boczny na desktopie: sortowanie, drzewo kategorii, lista kolekcji, cena |
| `products-catalog-mobile-filters.tsx` | te same filtry w arkuszu bocznym                                              |
| `products-catalog-price-filter.tsx`   | pola ceny minimalnej i maksymalnej                                            |
| `products-catalog-grid.tsx`           | siatka produktów i doładowywanie kolejnych stron                              |
| `products-catalog.loader.ts`          | `prefetchProductsCatalogPage`, wywoływany z każdego loadera trasy             |
| `products-catalog.utils.ts`           | `flattenStorefrontCategoryFilters`, `mapStorefrontCollectionFilters`          |

`useCatalogFilterSources` ukrywa filtr kategorii na stronie kategorii i filtr kolekcji na stronie kolekcji, całkowicie pomijając odpowiednie zapytanie — strona zawężona wykonuje więc o jedno zapytanie mniej.

`prefetchProductsCatalogPage` uruchamia równolegle zapytanie nieskończone i dwa zapytania źródeł filtrów, a następnie wywołuje `prefetchProductThumbnails` na elementach pierwszej strony.

Loadery `/categories/$handle` i `/collections/$handle` wyszukują swój wiersz i rozgrzewają siatkę w jednym `Promise.all`, więc zapytania o wiersz i o pierwszą stronę produktów są wysyłane jednocześnie. Wiersz pobiera `getStorefrontCategoryQuery(handle)` albo `getStorefrontCollectionQuery(handle)` pod kluczem `CATEGORY_QUERY_KEYS.BY_HANDLE` albo `COLLECTION_QUERY_KEYS.BY_HANDLE`, z 60-sekundowym czasem świeżości modułu. Odczyt obejmuje tylko `id`, `titles` i `descriptions`, czyli pola, których używają strona i handler produktów, dzięki czemu wiersz zapisywany przez render po stronie serwera w HTML-u pozostaje mały. Zmiana sortowania, filtra albo wstępne ładowanie po najechaniu na link tej samej strony korzysta z zapisanego wiersza i prosi serwer już tylko o produkty. Brakujący wiersz wraca jako `false`, bo cache zapytań nie przechowuje `undefined`. Strona kategorii rzuca wtedy `notFound`, a strona kolekcji rozgrzewa pozostałe kolekcje i nowości dla widoku niedostępnej kolekcji. Siatka rozgrzana równolegle dla nieistniejącego handle to opisana wyżej pusta strona.

## Nakładka wyszukiwania

Wyszukiwanie w nagłówku to oddzielna funkcja oparta na `src/modules/storefront-search`.

`searchStorefront` (`use-cases/search-storefront.ts`) jest publiczne, przyjmuje `{ locale, query }` i rozchodzi się na trzy akcesory w `storefront-search.server.ts`:

| Akcesor                       | Tabela               | Dopasowywane kolumny                                                                                                         |
| ----------------------------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `searchStorefrontProducts`    | `product`            | `titles`, `subtitles`, `tags`, `descriptions` i `handle` przez indeks `storefront_search`, za bramką `publishedInStockWhere` |
| `searchStorefrontCategories`  | `product_category`   | `handle`, `titles`, `subtitles`, `shortDescriptions`, status aktywny                                                         |
| `searchStorefrontCollections` | `product_collection` | `handle`, `titles`, `descriptions`, status aktywny                                                                           |

Grupa produktów w nakładce dopasowuje wyłącznie własny tekst produktu. W przeciwieństwie do parametru `q` nie dociera do produktów przez ich kategorie, kolekcje ani SKU.

Stałe w `storefront-search.constants.ts`:

- `STOREFRONT_SEARCH_MIN_LENGTH = 2` — zapytanie jest `enabled` dopiero od dwóch znaków
- `STOREFRONT_SEARCH_DEBOUNCE_MS = 300`
- `STOREFRONT_SEARCH_LIMIT_PER_GROUP = 6`
- `STOREFRONT_SEARCH_TRENDING_LIMIT = 5`

`getTrendingSearches` wypełnia stan pusty: bierze najwyżej uszeregowane aktywne kategorie i kolekcje po `rank`, potem `createdAt`, po `Math.ceil(5 / 2) = 3` z każdego źródła, i obcina połączoną listę do pięciu pozycji.

Interfejs to `search-overlay.tsx` w `.../landing-page/navigation/components/search/`, a jego logika w `.../navigation/hooks/use-search-overlay-logic.ts`. Ten hook dopasowuje też do frazy trzy zapisane na stałe strony statyczne z `src/data/static-pages.ts` (`/`, `/about`, `/blog`), używając funkcji `normalize` usuwającej znaki diakrytyczne, więc „o nas” dopasowuje się niezależnie od ogonków. Stan otwarcia trzyma store zustand w `.../navigation/store/navigation-store.ts`; nakładka jest animowana GSAP-em.

## Odświeżanie w czasie rzeczywistym

`STOREFRONT_REALTIME_QUERY_PREFIXES` w `src/integrations/realtime-invalidation/realtime-invalidation.subscriptions.ts` zawiera `PRODUCT_QUERY_KEYS.STOREFRONT_PAGE`, `CATEGORY_QUERY_KEYS.ALL`, `CATEGORY_QUERY_KEYS.BY_HANDLE`, `COLLECTION_QUERY_KEYS.ALL` i `COLLECTION_QUERY_KEYS.BY_HANDLE`. Mutacje katalogu w panelu wywołują `scheduleProductCatalogInvalidation()`, `scheduleCategoryCatalogInvalidation()` albo `scheduleCollectionCatalogInvalidation()`, więc otwarta strona katalogu odświeża dane bez przeładowania.
