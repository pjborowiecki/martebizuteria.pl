Every page in this chapter describes the code as it is in the repository, not as it is planned. A feature is **live** when it reads or writes real data through a module use case, Better Auth or Stripe. A **demo screen** renders constants from `src/data` and stores nothing. A **placeholder** renders copy from a message catalogue and has no data behind it at all.

Each page names the concrete files: the route in `src/routes`, the use cases in `src/modules/{feature}/use-cases`, the tables in `src/modules/{feature}/*.schema.ts` and the components in `src/presentation/components/custom`.

## Placeholders

- `/terms-of-service` renders a title, one paragraph and a link home from `messages/{locale}/pages.terms-of-service.json`. The two real legal documents are editable rows in D1. See [Legal pages](/docs/features/legal-pages).
- The newsletter form in `newsletter-section.tsx` is an `Input` and a `type="button"` with no handler. See [Landing page](/docs/features/landing-page).

## Schema without behaviour

Some tables are declared in `src/modules/*/`, exported from `src/integrations/drizzle-orm/drizzle.schemas.ts` and created by the migrations, but nothing reads or writes them yet:

| Table               | Module                                      | Why it is unused                                                                                   |
| ------------------- | ------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `discount`          | `src/modules/discount`                      | No code references it. See [Discounts](/docs/features/discounts).                                  |
| `cart`, `cart_item` | `src/modules/cart`, `src/modules/cart-item` | The basket lives in the browser. See [Cart](/docs/features/cart).                                  |
| `order_address`     | `src/modules/order-address`                 | Order addresses are read back through `checkout` → `address`. See [Orders](/docs/features/orders). |

## How to read a feature page

Every page follows the same shape:

1. **Routes** — the files under `src/routes` and the guards in their `beforeLoad`.
2. **Server functions** — the `createServerFn` exports in `use-cases/`, their middleware and their query or mutation options.
3. **Data** — the tables and columns the feature touches.
4. **Components** — the UI under `src/presentation/components/custom`.
5. **Related pages** — links onward.
