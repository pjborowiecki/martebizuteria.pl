## Two typefaces

M'Arte uses exactly two families, both self-hosted from `public/fonts` as subsetted WOFF2:

| Family                 | Role                        | Tailwind     | Files                                                    |
| ---------------------- | --------------------------- | ------------ | -------------------------------------------------------- |
| **Manrope**            | Body, UI, navigation, admin | `font-sans`  | One variable file per subset, weight axis `200 800`      |
| **Cormorant Garamond** | Display headings, editorial | `font-serif` | Static faces at 400, 500 and 600; italics at 400 and 500 |

`public/fonts` holds twelve web font files, and `public/fonts/forms` the three faces the PDF forms embed (see [Fonts in the PDF forms](#fonts-in-the-pdf-forms)). Each family has a `latin` and a `latin-ext` variant of every face, because Polish needs the extended range:

```
manrope-latin-wght-normal.woff2
manrope-latin-ext-wght-normal.woff2
cormorant-garamond-latin-400-normal.woff2
cormorant-garamond-latin-ext-400-normal.woff2
cormorant-garamond-latin-400-italic.woff2
cormorant-garamond-latin-ext-400-italic.woff2
cormorant-garamond-latin-500-normal.woff2
cormorant-garamond-latin-ext-500-normal.woff2
cormorant-garamond-latin-500-italic.woff2
cormorant-garamond-latin-ext-500-italic.woff2
cormorant-garamond-latin-600-normal.woff2
cormorant-garamond-latin-ext-600-normal.woff2
```

`public/_headers` serves `/fonts/*` with `Cache-Control: public, max-age=31536000, immutable`. The names carry no content hash, so replacing a font file means the old bytes may stay cached for a year — rename the file when you change its contents.

## Critical and deferred faces

The font CSS is deliberately split in two.

**`src/presentation/styles/critical-fonts.css`** carries only what the first screen needs: the two metric-matched fallback faces, Cormorant Garamond 400 normal (latin and latin-ext) and Manrope variable (latin and latin-ext), plus the `--font-sans` and `--font-serif` definitions on `:root`. It is inlined into the document head as a `<style>` tag, so no stylesheet request blocks the first paint:

```tsx
import criticalFontsCss from "~/src/presentation/styles/critical-fonts.css?raw"

export const StorefrontCriticalFontsHead = ({ locale }: Readonly<StorefrontCriticalFontsHeadProps>): JSX.Element => (
  <>
    {getCriticalFontPreloads(locale).map((link) => (
      <link key={link.href} {...link} />
    ))}
    <style dangerouslySetInnerHTML={CRITICAL_FONTS_STYLE_HTML} />
  </>
)
```

The root route renders it only outside the admin console:

```tsx
{
  !isAdmin && <StorefrontCriticalFontsHead locale={locale} />
}
```

**`src/presentation/styles/fonts.css`** carries the remaining eight Cormorant faces — 400 italic, 500 normal, 500 italic and 600 normal, each in both subsets. It is imported at the top of `globals.css`, so those faces arrive with the main stylesheet rather than blocking the head.

The fallback faces avoid layout shift by matching metrics:

```css
@font-face {
  font-family: "Manrope Fallback";
  src: local("Arial");
  size-adjust: 98.16%;
  ascent-override: 106.6%;
  descent-override: 30%;
  line-gap-override: 0%;
}
```

`globals.css` also sets `font-synthesis: none` on `body`, so a missing weight or italic is never faked by the browser.

## Locale-aware preloads

`src/presentation/document-assets.ts` exports one function. It preloads exactly two files — one body font, one display font — and switches subset on the locale:

```ts
export const getCriticalFontPreloads = (locale: SupportedLocale) => {
  const useLatinExt = locale === "pl-PL"

  return [
    {
      ...FONT_PRELOAD_BASE,
      href: useLatinExt ? "/fonts/manrope-latin-ext-wght-normal.woff2" : "/fonts/manrope-latin-wght-normal.woff2",
    },
    {
      ...FONT_PRELOAD_BASE,
      href: useLatinExt ? "/fonts/cormorant-garamond-latin-ext-400-normal.woff2" : "/fonts/cormorant-garamond-latin-400-normal.woff2",
    },
  ] as const
}
```

`FONT_PRELOAD_BASE` is `{ as: "font", crossOrigin: "anonymous", rel: "preload", type: "font/woff2" }`. `src/presentation/__test__/document-assets.test.ts` pins all of this: the exact hrefs per locale, the four attributes, and the fact that there are exactly two entries.

If you add a locale, extend the branch. If you add a third critical face, add it to `critical-fonts.css` _and_ to this function, or it will be fetched late.

## Fonts in the PDF forms

The withdrawal and complaint forms are made in the Worker with `pdf-lib` and `@pdf-lib/fontkit` (see [Legal pages: How the forms are made](/docs/features/legal-pages#how-the-forms-are-made)) and use the same two families, but not the web files above. Every web face is split into a `latin` and a `latin-ext` file, so a Polish word would need two fonts, and Manrope is a variable font, of which fontkit embeds only the default ExtraLight instance. `public/fonts/forms` holds three static TrueType faces instead:

| File                                | Face                                       | Source                                                                                  |
| ----------------------------------- | ------------------------------------------ | --------------------------------------------------------------------------------------- |
| `manrope-400-normal.ttf`            | Manrope Regular, version 4.504             | The static instance Google Fonts serves                                                 |
| `manrope-600-normal.ttf`            | Manrope SemiBold, version 4.504            | The static instance Google Fonts serves                                                 |
| `cormorant-garamond-600-normal.ttf` | Cormorant Garamond SemiBold, version 4.001 | The static instance Google Fonts serves, saved again with every glyph padded to 4 bytes |

Both families are under the SIL Open Font License 1.1 with no reserved font name. The licence must travel with every copy of the fonts, so `public/fonts/forms/OFL.txt` holds it with both copyright notices; it allows embedding the fonts in documents such as the forms. The Cormorant Garamond file is a modified version. Google Fonts stores its glyphs without padding, and fontkit's subsetter writes short `loca` offsets, which can only point at even positions, so most glyphs of the embedded subset came out broken. fontTools saved it again with `font["glyf"].padding = 4`, which changes nothing but the glyph table's padding.

A form embeds only the glyphs it uses, about 15 KB per form. The fonts are static assets, so they add nothing to the Worker's size, and `loadFormFonts` reads them through `ASSETS` each time a form is made. `/fonts/*` is cached for a year as immutable, so a changed form font needs a new file name, and `FORM_FONT_PATHS` in `src/presentation/pdf/form-document.ts` has to name it.

## Brand constants

`src/presentation/branding/app.ts` is the single source of the brand:

```ts
export const APP_DOMAIN = "martebizuteria.pl"
export const APP_URL = `https://${APP_DOMAIN}`
export const APP_GITHUB_OWNER = "pjborowiecki"
export const APP_GITHUB_REPO = APP_DOMAIN
export const APP_ICON = "/favicon.svg"
export const APP_NAME = "M'Arte"
export const DEFAULT_R2_PUBLIC_URL = "https://pub-a9ce13f98e72423eb72107a4e696f2e0.r2.dev"
export const OG_IMAGE_HEIGHT = "630"
export const OG_IMAGE_PATH = "/og.png"
export const OG_IMAGE_WIDTH = "1200"
export const THEME_COLOR = "#e7f3ec"
```

These feed more than the chrome:

| Constant                | Read by                                                                                                                                                                                                                                                                   |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `APP_NAME`              | `theme-init.ts` (the `localStorage` theme key), Better Auth, Stripe, Resend, the `og:site_name` and `title` meta, the auth and checkout headers                                                                                                                           |
| `APP_URL`, `APP_DOMAIN` | Canonical URLs, hreflang links and structured data (`src/lib/seo.ts`, `src/routes/__root.tsx`), the image host fallback (`src/lib/image.ts`), and through `APP_DOMAIN` the per-mode host list. Never email links or the Stripe return URL, which use the request's origin |
| `APP_ICON`              | The `icon` and `apple-touch-icon` links in the root route                                                                                                                                                                                                                 |
| `OG_IMAGE_*`            | The Open Graph and Twitter card meta in the root route, and the size `resolveProductSocialImageUrl` in `src/lib/image.ts` asks the image host for when a product page shows its own image                                                                                 |
| `THEME_COLOR`           | The `theme-color` meta tag                                                                                                                                                                                                                                                |
| `DEFAULT_R2_PUBLIC_URL` | The fallback public base for R2 assets in `src/lib/image.ts`                                                                                                                                                                                                              |

Because `THEME_STORAGE_KEY` is derived from `APP_NAME`, renaming the app changes the `localStorage` key and silently resets every visitor's stored theme. That is acceptable today (there is no switcher) but worth remembering.

## Seller details

The legal identity of the shop is data rather than a constant. The legal name, street, postal code, city, country, NIP, REGON, contact e-mail and phone are columns of the `store_setting` row, which the owner edits under **Settings → Store details**; `20261016160000_seller_details.sql` filled them with the details the code held until then (see [Admin settings](/docs/features/admin-settings#store-details)). The storefront reads them through `getSellerDetailsQuery()`, the admin through `getAdminSellerDetailsQuery()` and server code through `readSellerDetails()`, and two helpers in `src/modules/store-setting/store-setting.utils.ts` format them:

```ts
export const formatSellerPostalAddress = (
  { city, countryCode, legalName, postalCode, street }: Readonly<StoreSetting["sellerDetails"]>,
  locale: string,
): string[] => [legalName, street, `${postalCode} ${city}`, formatCountryName(countryCode, locale)]

export const toSellerPhoneHref = (phone: string): string => `tel:${phone.replaceAll(NOT_DIALLED, "")}`
```

`SellerContactDetails` in `src/presentation/components/custom/seller-contact-details.tsx` renders them in the storefront footer and in the contact section at the end of `/about`, every product page names the seller as the manufacturer in its "Manufacturer" section, the order e-mails and the newsletter name the seller with them, `sendEmail` uses the contact e-mail as every message's reply-to address, and `buildStoreStructuredData` and `buildProductStructuredData` in `src/lib/seo.ts`, handed the details as `seller`, publish the legal name, postal address, e-mail, phone and NIP in the home page's structured data and the legal name, postal address and e-mail as each product's manufacturer, so search engines read the same details customers do. The country is named from the stored code in the reader's language. The legal pages name the seller through store detail placeholders such as `:seller[nip]` (see [Legal pages](/docs/features/legal-pages#store-details-in-the-pages)).

So when the business details change, save them under Settings → Store details, and the storefront, the e-mails and the legal pages follow at once. The two PDF forms are made from the stored details each time they are opened. The pickup sentences in the terms and the FAQ, which write the street and city in words, still need an edit of their own. `APP_NAME` stays in `app.ts`, because it names the brand rather than the seller.

`src/presentation/branding/socials.ts` holds the two live profiles:

```ts
export const SOCIALS = {
  FACEBOOK: "https://www.facebook.com/p/MArte-Bi%C5%BCuteria-61567757976697/",
  INSTAGRAM: "https://www.instagram.com/m_arte.bizuteria/",
} as const
```

They are read by `src/lib/seo.ts` (the `sameAs` entries in structured data), the footer, and the fullscreen menu footer.

## Logo, icons and media

- The favicon is `public/favicon.svg`, wired through `APP_ICON`. There is no `.ico`.
- `public/og.png` is the 1200×630 social card.
- `src/presentation/components/custom/icons.tsx` holds two inline brand SVGs that Lucide does not cover: `GoogleIcon` and `FacebookIcon`. Everything else comes from `lucide-react`.
- `public/video/landing-video.mp4` is the landing-page footage; `public/screenshots` holds eight README stills.
- `public/icons.svg` is an SVG sprite with `bluesky`, `discord`, `documentation`, `github`, `social` and `x` symbols. Nothing in `src` references it; treat it as dead weight rather than an API.
