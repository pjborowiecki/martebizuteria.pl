## Dwa kroje pisma

M'Arte używa dokładnie dwóch rodzin, obie hostowane samodzielnie z `public/fonts` jako podzbiory WOFF2:

| Rodzina                | Rola                                     | Tailwind     | Pliki                                                 |
| ---------------------- | ---------------------------------------- | ------------ | ----------------------------------------------------- |
| **Manrope**            | Tekst, interfejs, nawigacja, panel       | `font-sans`  | Jeden plik zmienny na podzbiór, oś grubości `200 800` |
| **Cormorant Garamond** | Nagłówki ekspozycyjne, treści redakcyjne | `font-serif` | Kroje statyczne 400, 500 i 600; kursywy 400 i 500     |

W `public/fonts` leży dwanaście plików fontów strony, a w `public/fonts/forms` trzy kroje, które osadzają formularze PDF (zobacz [Fonty w formularzach PDF](#fonty-w-formularzach-pdf)). Każda rodzina ma wariant `latin` i `latin-ext` każdego kroju, bo polszczyzna potrzebuje zakresu rozszerzonego:

```
manrope-latin-wght-normal.woff2
manrope-latin-ext-wght-normal.woff2
cormorant-garamond-latin-400-normal.woff2
cormorant-garamond-latin-ext-400-normal.woff2
cormorant-garamond-latin-400-italic.woff2
cormorant-garamond-latin-ext-400-italic.woff2
cormorant-garamond-latin-500-normal.woff2
cormorant-garamond-latin-ext-500-normal.woff2
cormorant-garamond-latin-500-italic.woff2
cormorant-garamond-latin-ext-500-italic.woff2
cormorant-garamond-latin-600-normal.woff2
cormorant-garamond-latin-ext-600-normal.woff2
```

`public/_headers` serwuje `/fonts/*` z nagłówkiem `Cache-Control: public, max-age=31536000, immutable`. Nazwy nie zawierają skrótu treści, więc po podmianie pliku stare bajty mogą zostać w cache nawet rok — zmieniając zawartość, zmień też nazwę pliku.

## Kroje krytyczne i odroczone

CSS fontów jest świadomie podzielony na dwie części.

**`src/presentation/styles/critical-fonts.css`** zawiera tylko to, czego potrzebuje pierwszy ekran: dwa kroje zastępcze dopasowane metrycznie, Cormorant Garamond 400 normal (latin i latin-ext), zmienny Manrope (latin i latin-ext) oraz definicje `--font-sans` i `--font-serif` w `:root`. Jest wklejany do sekcji `head` jako znacznik `<style>`, więc żadne żądanie arkusza nie blokuje pierwszego renderu:

```tsx
import criticalFontsCss from "~/src/presentation/styles/critical-fonts.css?raw"

export const StorefrontCriticalFontsHead = ({ locale }: Readonly<StorefrontCriticalFontsHeadProps>): JSX.Element => (
  <>
    {getCriticalFontPreloads(locale).map((link) => (
      <link key={link.href} {...link} />
    ))}
    <style dangerouslySetInnerHTML={CRITICAL_FONTS_STYLE_HTML} />
  </>
)
```

Trasa główna renderuje go wyłącznie poza konsolą administratora:

```tsx
{
  !isAdmin && <StorefrontCriticalFontsHead locale={locale} />
}
```

**`src/presentation/styles/fonts.css`** zawiera pozostałe osiem krojów Cormorant — 400 kursywa, 500 normal, 500 kursywa i 600 normal, każdy w obu podzbiorach. Jest importowany na początku `globals.css`, więc te kroje przychodzą razem z głównym arkuszem, nie blokując sekcji `head`.

Kroje zastępcze unikają przeskoku układu, dopasowując metryki:

```css
@font-face {
  font-family: "Manrope Fallback";
  src: local("Arial");
  size-adjust: 98.16%;
  ascent-override: 106.6%;
  descent-override: 30%;
  line-gap-override: 0%;
}
```

`globals.css` ustawia też `font-synthesis: none` na `body`, więc brakująca grubość ani kursywa nigdy nie zostaną podrobione przez przeglądarkę.

## Preloady zależne od języka

`src/presentation/document-assets.ts` eksportuje jedną funkcję. Preloaduje dokładnie dwa pliki — jeden font tekstowy i jeden ekspozycyjny — i przełącza podzbiór zależnie od języka:

```ts
export const getCriticalFontPreloads = (locale: SupportedLocale) => {
  const useLatinExt = locale === "pl-PL"

  return [
    {
      ...FONT_PRELOAD_BASE,
      href: useLatinExt ? "/fonts/manrope-latin-ext-wght-normal.woff2" : "/fonts/manrope-latin-wght-normal.woff2",
    },
    {
      ...FONT_PRELOAD_BASE,
      href: useLatinExt ? "/fonts/cormorant-garamond-latin-ext-400-normal.woff2" : "/fonts/cormorant-garamond-latin-400-normal.woff2",
    },
  ] as const
}
```

`FONT_PRELOAD_BASE` to `{ as: "font", crossOrigin: "anonymous", rel: "preload", type: "font/woff2" }`. Plik `src/presentation/__test__/document-assets.test.ts` przypina to wszystko: dokładne adresy dla każdego języka, cztery atrybuty i fakt, że wpisów jest dokładnie dwa.

Dodając język, rozszerz warunek. Dodając trzeci krój krytyczny, dopisz go do `critical-fonts.css` _oraz_ do tej funkcji, inaczej zostanie pobrany za późno.

## Fonty w formularzach PDF

Formularze odstąpienia i reklamacji powstają w Workerze przez `pdf-lib` i `@pdf-lib/fontkit` (zobacz [Strony prawne: Jak powstają formularze](/docs/features/legal-pages#jak-powstają-formularze)) i używają tych samych dwóch rodzin, ale nie powyższych plików strony. Każdy krój strony jest podzielony na plik `latin` i `latin-ext`, więc polskie słowo potrzebowałoby dwóch fontów, a Manrope jest fontem zmiennym, z którego fontkit osadza tylko domyślną odmianę ExtraLight. Dlatego w `public/fonts/forms` leżą trzy statyczne kroje TrueType:

| Plik                                | Krój                                      | Źródło                                                                                                  |
| ----------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `manrope-400-normal.ttf`            | Manrope Regular, wersja 4.504             | Statyczna odmiana, którą serwuje Google Fonts                                                           |
| `manrope-600-normal.ttf`            | Manrope SemiBold, wersja 4.504            | Statyczna odmiana, którą serwuje Google Fonts                                                           |
| `cormorant-garamond-600-normal.ttf` | Cormorant Garamond SemiBold, wersja 4.001 | Statyczna odmiana, którą serwuje Google Fonts, zapisana ponownie z każdym glifem wyrównanym do 4 bajtów |

Obie rodziny są na licencji SIL Open Font License 1.1, bez zastrzeżonej nazwy fontu. Licencja musi towarzyszyć każdej kopii fontów, więc `public/fonts/forms/OFL.txt` zawiera ją z obiema informacjami o prawach autorskich; pozwala ona osadzać fonty w dokumentach, takich jak formularze. Plik Cormorant Garamond jest wersją zmodyfikowaną. Google Fonts zapisuje jego glify bez wyrównania, a podzbiór, który tworzy fontkit, ma krótkie przesunięcia `loca`, wskazujące tylko parzyste pozycje, więc większość glifów osadzonego podzbioru wychodziła uszkodzona. fontTools zapisał go ponownie z `font["glyf"].padding = 4`, co zmienia tylko wyrównanie tabeli glifów.

Formularz osadza tylko użyte glify, około 15 KB na formularz. Fonty są zasobami statycznymi, więc nie zwiększają rozmiaru Workera, a `loadFormFonts` czyta je przez `ASSETS` za każdym razem, gdy powstaje formularz. `/fonts/*` jest cache'owane przez rok jako niezmienne, więc zmieniony font formularzy potrzebuje nowej nazwy pliku, którą musi podać `FORM_FONT_PATHS` w `src/presentation/pdf/form-document.ts`.

`src/presentation/branding/app.ts` jest jedynym źródłem prawdy o marce:

```ts
export const APP_DOMAIN = "martebizuteria.pl"
export const APP_URL = `https://${APP_DOMAIN}`
export const APP_GITHUB_OWNER = "pjborowiecki"
export const APP_GITHUB_REPO = APP_DOMAIN
export const APP_ICON = "/favicon.svg"
export const APP_NAME = "M'Arte"
export const DEFAULT_R2_PUBLIC_URL = "https://pub-a9ce13f98e72423eb72107a4e696f2e0.r2.dev"
export const OG_IMAGE_HEIGHT = "630"
export const OG_IMAGE_PATH = "/og.png"
export const OG_IMAGE_WIDTH = "1200"
export const THEME_COLOR = "#e7f3ec"
```

Zasilają one znacznie więcej niż chrom strony:

| Stała                   | Czytana przez                                                                                                                                                                                                                                                                          |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `APP_NAME`              | `theme-init.ts` (klucz motywu w `localStorage`), Better Auth, Stripe, Resend, meta `og:site_name` i `title`, nagłówki logowania i kasy                                                                                                                                                 |
| `APP_URL`, `APP_DOMAIN` | Adresy kanoniczne, linki hreflang i dane strukturalne (`src/lib/seo.ts`, `src/routes/__root.tsx`), zapasowy host obrazów (`src/lib/image.ts`), a przez `APP_DOMAIN` lista hostów dla każdego trybu. Nigdy linki w e-mailach ani adres powrotu ze Stripe, które używają originu żądania |
| `APP_ICON`              | Linki `icon` i `apple-touch-icon` w trasie głównej                                                                                                                                                                                                                                     |
| `OG_IMAGE_*`            | Meta Open Graph i karty Twittera w trasie głównej oraz rozmiar, o który `resolveProductSocialImageUrl` z `src/lib/image.ts` prosi host obrazów, gdy strona produktu pokazuje własne zdjęcie                                                                                            |
| `THEME_COLOR`           | Znacznik meta `theme-color`                                                                                                                                                                                                                                                            |
| `DEFAULT_R2_PUBLIC_URL` | Zapasowa publiczna baza zasobów R2 w `src/lib/image.ts`                                                                                                                                                                                                                                |

Ponieważ `THEME_STORAGE_KEY` wywodzi się z `APP_NAME`, zmiana nazwy aplikacji zmienia klucz w `localStorage` i po cichu resetuje zapisany motyw każdemu odwiedzającemu. Dziś to nieszkodliwe (nie ma przełącznika), ale warto o tym pamiętać.

## Dane sprzedawcy

Tożsamość prawna sklepu to dane, a nie stała. Pełna nazwa firmy, ulica, kod pocztowy, miejscowość, kraj, NIP, REGON, e-mail kontaktowy i telefon to kolumny wiersza `store_setting`, które właściciel zmienia w **Ustawienia → Dane sklepu**; `20261016160000_seller_details.sql` wypełniła je danymi, które do tej pory były w kodzie (zobacz [Ustawienia panelu](/docs/features/admin-settings#dane-sklepu)). Sklep czyta je przez `getSellerDetailsQuery()`, panel przez `getAdminSellerDetailsQuery()`, a kod serwerowy przez `readSellerDetails()`, a dwie funkcje pomocnicze w `src/modules/store-setting/store-setting.utils.ts` je formatują:

```ts
export const formatSellerPostalAddress = (
  { city, countryCode, legalName, postalCode, street }: Readonly<StoreSetting["sellerDetails"]>,
  locale: string,
): string[] => [legalName, street, `${postalCode} ${city}`, formatCountryName(countryCode, locale)]

export const toSellerPhoneHref = (phone: string): string => `tel:${phone.replaceAll(NOT_DIALLED, "")}`
```

`SellerContactDetails` z `src/presentation/components/custom/seller-contact-details.tsx` pokazuje je w stopce sklepu i w sekcji kontaktowej na końcu `/about`, każda karta produktu podaje sprzedawcę jako producenta w sekcji „Producent”, e-maile o zamówieniach i newsletter wymieniają z nimi sprzedawcę, `sendEmail` ustawia e-mail kontaktowy jako adres odpowiedzi każdej wiadomości, a `buildStoreStructuredData` i `buildProductStructuredData` w `src/lib/seo.ts`, które dostają dane jako `seller`, publikują nazwę prawną, adres pocztowy, e-mail, telefon i NIP w danych strukturalnych strony głównej oraz nazwę prawną, adres pocztowy i e-mail jako producenta każdego produktu, więc wyszukiwarki czytają te same dane co klienci. Kraj jest nazwany na podstawie zapisanego kodu w języku czytelnika. Strony prawne podają sprzedawcę przez znaczniki danych sklepu, na przykład `:seller[nip]` (zobacz [Strony prawne](/docs/features/legal-pages#dane-sklepu-na-stronach)).

Gdy więc dane firmy się zmienią, wystarczy zapisać je w Ustawienia → Dane sklepu, a sklep, e-maile i strony prawne od razu za nimi pójdą. Dwa formularze PDF powstają z zapisanych danych przy każdym otwarciu. Zdania o odbiorze w regulaminie i w FAQ, które podają ulicę i miejscowość słowami, nadal wymagają osobnej zmiany. `APP_NAME` zostaje w `app.ts`, bo nazywa markę, a nie sprzedawcę.

`src/presentation/branding/socials.ts` przechowuje dwa aktywne profile:

```ts
export const SOCIALS = {
  FACEBOOK: "https://www.facebook.com/p/MArte-Bi%C5%BCuteria-61567757976697/",
  INSTAGRAM: "https://www.instagram.com/m_arte.bizuteria/",
} as const
```

Czytają je `src/lib/seo.ts` (wpisy `sameAs` w danych strukturalnych), stopka oraz stopka menu pełnoekranowego.

## Logo, ikony i multimedia

- Favikona to `public/favicon.svg`, podłączona przez `APP_ICON`. Nie ma pliku `.ico`.
- `public/og.png` to karta społecznościowa 1200×630.
- `src/presentation/components/custom/icons.tsx` przechowuje dwa wbudowane SVG marek, których nie pokrywa Lucide: `GoogleIcon` i `FacebookIcon`. Wszystko pozostałe pochodzi z `lucide-react`.
- `public/video/landing-video.mp4` to materiał wideo strony głównej; `public/screenshots` zawiera osiem zrzutów do README.
- `public/llms.txt` to statyczny plik `llms.txt` dla modeli językowych: jednozdaniowy opis sklepu, zasada, że polski nie ma prefiksu, a angielski działa pod `/en-US/`, oraz odnośniki do stron sklepu, zwrotów, regulaminu, polityki prywatności, „o nas” i FAQ, z adnotacją, że konto, kasa i panel administracyjny nie należą do publicznej części strony.
- `public/icons.svg` to sprite SVG z symbolami `bluesky`, `discord`, `documentation`, `github`, `social` i `x`. Nic w `src` się do niego nie odwołuje — traktuj go jako pozostałość, nie jako API.
