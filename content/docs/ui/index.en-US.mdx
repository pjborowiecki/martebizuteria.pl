Everything visual lives under `src/presentation`. Nothing else in the repository owns colour, type, spacing or markup: routes place components, modules return data, and the presentation layer decides how it looks.

| Path                                  | Contents                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/presentation/components/shadcn/` | 57 generated shadcn/ui primitives, `base-lyra` style, built on Base UI                                                                                                                                                                                                                                                                             |
| `src/presentation/components/custom/` | Application components: flat shared files (`image.tsx`, `product-card.tsx`, `localized-link.tsx`, `icons.tsx`, …), the `datagrid/`, `checkout/` and `image-upload/` kits, the router `defaults/` (error, not-found and pending components, default messages), the `display-preferences/` field and hooks, and one folder per screen under `pages/` |

## Two shells, one token set

The application renders two visually different shells from the same token definitions.

- **Storefront look**: serif display type, generous spacing, Lenis smooth scrolling for mouse and trackpad, light and dark token sets. `src/routes/_storefront.tsx` is the layout for the public pages and wraps them with `Navigation` and `Footer`; `account.tsx`, `auth.tsx`, `checkout.tsx` and `docs.tsx` are separate top-level layouts that use the same tokens: `account.tsx` and `docs.tsx` reuse the same `Navigation` and `Footer`, `auth.tsx` reuses `Navigation` only, and `checkout.tsx` renders its own `CheckoutHeader`.
- **Admin look** (`/admin/**`): a dense console. `src/routes/admin.tsx` forces light tokens inside `[data-admin-main]`, paints the page chrome with the dark sidebar colour and skips smooth scrolling.

The root route (`src/routes/__root.tsx`) decides which one it is with `isAdminPathname(...)` and sets `data-admin-shell` on `html` accordingly. See [Theme](/docs/ui/theme) for the inline scripts that make this happen before first paint.

## Screen folders

`src/presentation/components/custom/pages/` has one folder per area: `account`, `admin`, `auth`, `cart-page`, `categories`, `collections`, `content-page`, `docs`, `landing-page`, `newsletter`, `product-page`, `products-catalog`, `withdrawal`. Larger areas subdivide further — the admin orders screen, for example, is `orders/components/`, `orders/hooks/`, `orders/lib/`, `orders/detail/`, `orders/summary/` and `orders/utils/`.

Every folder keeps its tests beside it in `__test__/`. Tests that need the DOM run in jsdom and are named `<file>.component.test.tsx`, or `<file>.component.test.ts` when they contain no JSX; tests of pure helpers and server-rendering checks are named `<file>.test.ts` or `<file>.test.tsx` and run in the `node` project. Run the component tests with:

```bash
bun run test:component
```
