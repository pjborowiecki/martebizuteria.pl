`src/presentation/components/shadcn/` holds 58 files: 57 primitives generated by the shadcn CLI in the `base-lyra` style, plus `sheet-control.styles.ts`, which is class strings rather than a component. **They are built on Base UI, not Radix.** Thirty-one of them re-export `@base-ui/react` parts with project classes; the rest wrap another library or are plain markup. Screens import primitives directly — there are no wrappers around them.

`components.json` records the setup:

```json
{
  "style": "base-lyra",
  "tailwind": { "css": "~/src/presentation/styles/globals.css", "baseColor": "neutral", "cssVariables": true },
  "iconLibrary": "lucide",
  "aliases": {
    "components": "~/src/presentation/components",
    "utils": "cn",
    "ui": "~/src/presentation/components/shadcn",
    "lib": "~/src/lib",
    "hooks": "~/src/hooks"
  }
}
```

The `utils` alias is the bare package name `cn` — `cn@0.3` from the shadcn project, a compiled `clsx` + `tailwind-merge` replacement — so every component does `import { cn } from "cn"`, not from a local file.

## Base UI conventions

If you have written Radix shadcn before, these are the differences that actually bite:

| Radix habit                    | Base UI here                                                |
| ------------------------------ | ----------------------------------------------------------- |
| `asChild` on a trigger         | `render={<TheElement />}` — a rendered element, not a child |
| `onSelect` on a menu item      | `onClick`                                                   |
| `checked="indeterminate"`      | `checked` stays a boolean; `indeterminate` is its own prop  |
| `data-state="checked"`         | `data-checked` / `data-unchecked`                           |
| `data-state="open"`            | `data-popup-open` (popups) or `data-open`                   |
| `data-disabled` on the wrapper | `data-disabled` on the part itself                          |

`Button` renders a real `<button>`, so `onClick` and `disabled` work as they do in the DOM. Dialogs, menus, popovers and sheets are controlled with `open` and `onOpenChange`. `Select` takes `items`, `value` and `onValueChange` on the root and a `SelectValue` inside `SelectTrigger`.

The `render` prop expects an element, and an element created during render is a new object on every pass, so hoist it:

```tsx
const trigger = useMemo(
  () => (
    <Button variant="ghost" size="icon" className="size-8">
      <MoreHorizontal className="size-4" strokeWidth={1.5} />
    </Button>
  ),
  [],
)

return (
  <DropdownMenu open={menuOpen} onOpenChange={handleMenuOpenChange}>
    <DropdownMenuTrigger render={trigger} />
    <DropdownMenuContent align="end" className="min-w-52 p-1.5">
      …
    </DropdownMenuContent>
  </DropdownMenu>
)
```

Nesting a trigger inside another trigger is done the same way — the data grid's column-visibility button is a `DropdownMenuTrigger` rendered into a `TooltipTrigger`:

```tsx
const menuTrigger = useMemo(() => <DropdownMenuTrigger render={button} />, [button])
…
<TooltipTrigger render={menuTrigger} />
```

`Tooltip.Provider` is mounted once, in `src/routes/__root.tsx`, with `delay={0}`.

## Variants worth knowing

`Button` (`button.tsx`) is the widest primitive. Variants: `default`, `secondary`, `outline`, `ghost`, `link`, `destructive`, plus the storefront account set `account`, `account-outline`, `account-ghost`, `account-destructive`. Sizes: `xs`, `sm`, `default`, `lg`, `xl`, `icon-xs`, `icon-sm`, `icon`, `icon-lg`, `account`, `account-sm`. The admin console uses `outline` with `icon-lg` or `icon-sm`; the storefront uses the `account-*` set, which is uppercase with wide tracking.

`Input` (`input.tsx`) has six variants and no default border radius — the shop's inputs are underlines, not boxes:

| Variant          | Used by                                                        |
| ---------------- | -------------------------------------------------------------- |
| `default`        | Most forms: bottom border, `min-h-11`, focuses to `foreground` |
| `floating`       | Checkout and account forms, paired with `FloatingLabel`        |
| `account`        | Inline account editing: bottom border only, 14px               |
| `account-inline` | Borderless inline editing                                      |
| `sheet`          | Admin sheet panels, via `sheet-control.styles.ts`              |
| `sheet-inset`    | Inputs inside an `InputGroup` in a sheet                       |

`sheet-control.styles.ts` is not a component — it exports the class strings (`SHEET_CONTROL_HEIGHT`, `sheetInputClassName`, `sheetInputGroupClassName`, `sheetSelectTriggerClassName`, …) that keep every control in an admin sheet at the same 40px height and `rounded-lg` corner. `globals.css` adds a components-layer rule forcing `var(--radius)` on inputs, selects, input groups and textareas inside `[data-slot="sheet-content"]`.

## Forms

Forms use **react-hook-form** with Zod resolvers, not TanStack Form. The primitives involved are `Field`, `FieldGroup`, `FieldLabel`, `FieldError` (`field.tsx`), `Input`, `InputGroup` and the shared helpers in `src/presentation/components/custom/floating-field.tsx`.

A field from `checkout/components/checkout-fields.tsx`:

```tsx
const { field, fieldState } = useController({ control, name })

const valueStr = displayValue ?? toStringValue(field.value)
const showValid = !isReadOnly && isFieldValid(fieldState, valueStr)

return (
  <Field className={cn("relative", className)} data-invalid={fieldState.invalid}>
    <Input
      {...rest}
      {...field}
      variant="floating"
      value={valueStr}
      placeholder=" "
      id={field.name}
      aria-invalid={fieldState.invalid}
      aria-required={required}
      className={cn("peer", showValid && VALID_INPUT_CLASS)}
    />
    <FloatingLabel htmlFor={field.name} label={label} required={required} />
    <ValidCheck show={showValid} />
    <FieldErrorMessage fieldState={fieldState} />
  </Field>
)
```

The floating label is a sibling `<label>` driven entirely by CSS: `FLOATING_LABEL_CLASS` uses `peer-focus:` and `peer-[:not(:placeholder-shown)]:` to lift and shrink it, which is why the input needs `placeholder=" "` and `className="peer"`. `ValidCheck` shows a green tick once `fieldState.isTouched && !fieldState.invalid && value !== ""`.

For server-side and shared validation messages use `ValidationFieldError` (`custom/validation-field-error.tsx`). It takes a message key and a namespace, looks the key up with `t.has`, and falls back to the generic `errors.action.VALIDATION` message when the key is missing — so an unmapped Zod code degrades to a sane sentence instead of rendering the raw code.

## Translations

Primitives that need words read them themselves from the `components.shadcn` namespace: `breadcrumb.navLabel`, `carousel.nextSlide`, `dialog.close`, `command.title`, `pagination.*` and `sheet.close`. Never pass a label into a primitive as a prop when the primitive already has a key. Add new strings to `messages/en-US/components.shadcn.json` **and** `messages/pl-PL/components.shadcn.json`.

## CSS size

`globals.css` excludes unused primitives from Tailwind's source scan, so their classes are never compiled:

```css
@source not "../components/shadcn/{alert,button-group,context-menu,drawer,empty,hover-card,input-otp,item,kbd,menubar,native-select,navigation-menu,pagination,progress,resizable,scroll-area,slider,tabs,toggle-group,toggle,typography}.tsx";
```

It also excludes `**/*.{test,spec}.{ts,tsx}`, `**/__test__/**` and `platform/testing/**`.

**When you start using one of the excluded primitives, remove it from that list**, or it will render unstyled. Conversely, if you stop using one, add it back.

## Known rough edges

- `typography.tsx` (`H1` … `H4`, `P`, `Lead`, `Large`, `Small`, `Muted`, `Blockquote`, `InlineCode`, `List`, `TableWrap`, `Prose`) is not imported anywhere and is in the `@source not` list. Its `Prose` component applies `prose`, `prose-neutral` and `prose-headings:*` classes, but `globals.css` registers `@tailwindcss/typography` under `classname: wysiwyg`, so the `prose*` utilities do not exist in this build. Use the MDX component map in `custom/mdx.tsx` for prose instead, or fix `Prose` to use `wysiwyg` before relying on it.
- `Spinner` hard-codes `aria-label="Loading"` in English rather than reading a message key.
