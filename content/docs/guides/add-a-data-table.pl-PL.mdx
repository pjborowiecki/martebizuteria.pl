Każda tabela listy w panelu M'Arte — produkty, kategorie, kolekcje, atrybuty, zamówienia, klienci, kupony, subskrybenci newslettera i dziennik zdarzeń — jest zbudowana na jednej wspólnej tabeli danych w `src/presentation/components/custom/datagrid/`. Owija ona TanStack Table v9 i dokłada zmianę szerokości kolumn, przeciąganie kolumn, przypinanie, zapamiętywane per użytkownik preferencje, stan szkieletowy podczas ładowania, pole wyszukiwania, przeciąganie wierszy i stronicowanie. Krótkie listy tylko do odczytu, takie jak kampanie newslettera (`newsletter-campaigns-table.tsx`) i ostatnie zamówienia na stronie podsumowania panelu, używają zamiast tego zwykłej `Table` z shadcn.

Najczytelniejszym przykładem od początku do końca jest tabela kategorii w `src/presentation/components/custom/pages/admin/catalog/categories/`. Ten przewodnik idzie jej śladem.

## 1. Utwórz przestrzeń tabeli

Jeden plik, eksportujący jedną tabelę. Z `.../categories/utils/categories-data-grid.ts`:

```ts
import { type ProductCategory } from "~/src/modules/product-category/product-category.types"

import { createDataGrid } from "~/src/presentation/components/custom/datagrid/components/create-data-grid"

export const CATEGORIES_DATA_GRID_KEY = "admin.catalog.categories"

export const categoriesDataGrid = createDataGrid<ProductCategory["adminListItem"]>({
  persistenceKey: CATEGORIES_DATA_GRID_KEY,
})
```

`createDataGrid` zwraca `{ Body, Export, Pagination, Provider, Toolbar, persistenceKey, useDataGrid }` — prywatny kontekst React plus pięć komponentów, które z niego czytają. Każda tabela dostaje własny kontekst, więc dwie tabele na jednej stronie nigdy nie dzielą stanu.

`persistenceKey` jest kluczem przechowywania. Preferencje zapisują się pod `marte:datagrid:v1:<persistenceKey>` w `localStorage`, a wbudowany skrypt z `datagrid/datagrid-init.ts` — wstawiany przez `src/routes/__root.tsx` — czyta je przed hydratacją i ustawia na `<html>` zmienne CSS `--marte-dg-<slug>-<column>`, żeby szerokości kolumn nie skakały przy pierwszym renderowaniu. **Zmiana `persistenceKey` odrzuca zapisany układ tej tabeli u każdego użytkownika.**

## 2. Zdefiniuj kolumny

Kolumny mieszkają w hooku, żeby nagłówki dały się tłumaczyć, a komórki mogły formatować według preferencji wyświetlania administratora. Bierz `useFormatter` z `~/src/hooks/use-display-format`, a nie z `use-intl/react`: jest związany z lokalizacją formatu i strefą czasową administratora. Z `.../categories/components/categories-columns.tsx`:

```tsx
export const useCategoryColumns = () => {
  const t = useTranslations("pages.admin.catalog.categories")
  const tAdmin = useTranslations("pages.admin")
  const format = useFormatter()
  const locale = useLocale()

  return useMemo(() => buildCategoryDataGridColumns({ format, locale, t, tAdmin }), [format, locale, t, tAdmin])
}
```

```tsx
columnHelper.accessor("createdAt", {
  cell: ({ getValue }) => <span className="text-muted-foreground">{format.dateTime(new Date(getValue()), { dateStyle: "medium" })}</span>,
  header: t("columns.createdAt"),
  id: CATEGORY_TABLE_COLUMN_ID.createdAt,
  maxSize: 320,
  meta: {
    skeletonVariant: "date",
  },
  minSize: CATEGORY_TABLE_COLUMN_SIZE.createdAt,
  size: CATEGORY_TABLE_COLUMN_SIZE.createdAt,
})
```

`columnHelper` to `createColumnHelper<DataGridFeatures, ProductCategory["adminListItem"]>()`, zadeklarowany raz na końcu pliku. `useLocale()` służy tu wyłącznie do wyboru przetłumaczonego tytułu, podtytułu i opisów wiersza; niczego nie formatuje.

Ceny przechodzą przez `formatPrice(amountInMinorUnits, currency, locale)` z `src/modules/_core/utils/currency.ts`, z lokalizacją z `useFormatLocale()`. Kolumna ceny w tabeli produktów (`.../catalog/products/components/products-columns.tsx`, gdzie `useProductColumns` odczytuje `const formatLocale = useFormatLocale()`):

```tsx
columnHelper.accessor("minPrice", {
  cell: ({ getValue }) => {
    const price = getValue()
    if (price === undefined) {
      return <span className="text-muted-foreground/40">{EMPTY_VALUE}</span>
    }

    return <span className="block font-mono text-sm font-medium tabular-nums">{formatPrice(price, "PLN", formatLocale)}</span>
  },
  filterFn: matchesNumericColumnFilter,
  header: t("columns.price"),
  id: PRODUCT_TABLE_COLUMN_ID.minPrice,
  meta: {
    skeletonVariant: "number",
  },
  minSize: PRODUCT_TABLE_COLUMN_SIZE.minPrice,
  size: PRODUCT_TABLE_COLUMN_SIZE.minPrice,
})
```

Argument waluty zależy od tabeli: tabela produktów przekazuje `"PLN"`, tabela kuponów `STORE_CURRENCY_CODE` z `src/modules/_core/constants/currency.ts`, a tabela zamówień `currencyCode` każdego wiersza.

Konwencje:

- `id` pochodzi z mapy `*_TABLE_COLUMN_ID` modułu, a `size` i `minSize` z `*_TABLE_COLUMN_SIZE` — oba w pliku stałych modułu. Zapamiętane preferencje są kluczowane identyfikatorem kolumny, więc identyfikator jest tak trwały jak `persistenceKey`.
- `meta` ma typ `DataGridColumnMeta`. Dostępne opcje to `cellClassName`, `headClassName`, `fillsRemainingWidth`, `absorbsTrailingSlack`, `exportValue`, `filterOnly`, `preventRowClick` i `skeletonVariant`. `exportValue` włącza kolumnę do eksportu; opisuje go krok 5. `skeletonVariant` wybiera kształt zaślepki podczas pobierania danych: `badge`, `checkbox`, `date`, `icon`, `iconEnd`, `number`, `recordId`, `text`, `thumbnail` albo `title`.
- Kolumny pomocnicze to `select`, `drag`, `image` i `actions` — identyfikatory wymienione w `DATAGRID_UTILITY_COLUMN_IDS` w `datagrid/lib/data-grid.utils.ts`. Są zawsze widoczne i wyłączone z zapamiętywanych rozmiarów. Ustaw im stałą szerokość przez `fixedDataGridColumnWidth(size)`, które zwraca spójne `size`, `minSize` i `maxSize` oraz `enableResizing: false`.
- Nagłówek da się przeciągnąć w inne miejsce tylko wtedy, gdy kolumnę można ukryć, więc `enableHiding: false` (ustawione na `drag` i `actions` oraz wewnątrz `selectionColumn`) trzyma też kolumnę w miejscu.
- Kolumna z polami wyboru to `selectionColumn(columnHelper, { all: t(...), row: t(...) })`, z etykietami pobieranymi z `*_TABLE_A11Y_KEYS` modułu.
- Większość komórek to krótkie domknięcia w miejscu. Wszystko większe jest komponentem: `CategoryImageCell` jest zadeklarowany nad budownikami, a wspólne komórki, takie jak `CatalogTitleHandleCell`, `CatalogTruncatedTextCell` i `CatalogStatusBadge`, pochodzą z `pages/admin/catalog/table/components/`.

Ponieważ prawdziwa tabela katalogu ma więcej kolumn, niż pozwala funkcja o 150 liniach, budownik się dzieli: `buildCategoryTimestampColumns(context)` zwraca dwie kolumny znaczników czasu, a `buildCategoryDataGridColumns(context)` rozwija je we własnym `columnHelper.columns([...])` przed kolumną `actions`. Hook wywołuje wyłącznie `buildCategoryDataGridColumns`.

## 3. Zbuduj instancję tabeli

Hook `use-<entity>-data-grid.ts` ładuje dane i zwraca `DataGridContextValue`:

```ts
const { data: categories, isFetching } = useSuspenseQuery(getAdminCategoriesQuery())
const columns = useCategoryColumns()
const initialColumnOrder = useMemo(() => getDataGridColumnIds(columns), [columns])

const { columnReorder, hasPreferenceOverrides, resetPreferences, table } = useDataGridInstance({
  columns,
  data: ordering.items,
  defaultColumnVisibility: CATEGORY_TABLE_DEFAULT_COLUMN_VISIBILITY,
  getRowId: (row) => row.id,
  globalFilterFn,
  initialColumnOrder,
  initialColumnPinning: CATEGORY_TABLE_COLUMN_PINNING,
  persistenceKey: categoriesDataGrid.persistenceKey,
})
```

`useDataGridInstance` ustawia `columnResizeMode: "onChange"`, włącza przypinanie, zmianę szerokości i zaznaczanie wierszy, stosuje zestaw `dataGridFeatures`, wylicza rozmiary minimalne i maksymalne z definicji kolumn i przekazuje powstały stan do `useDataGridPreferences`. Wszystko, czego potrzebuje, jest w opcjach — nie buduj własnego wywołania `useTable`.

Hook zwraca wartość kontekstu, jakiej oczekują komponenty tabeli:

```ts
return useMemo(
  () => ({
    columnReorder,
    hasPreferenceOverrides,
    isLoading: showSkeletonRows,
    onRowClick,
    persistenceKey: categoriesDataGrid.persistenceKey,
    resetPreferences,
    rowReorder,
    searchPlaceholder: t("searchPlaceholder"),
    table,
  }),
  [columnReorder, hasPreferenceOverrides, onRowClick, resetPreferences, rowReorder, showSkeletonRows, t, table],
)
```

### Wyszukiwanie po stronie klienta

`createCatalogTableGlobalFilterFn` przyjmuje funkcję z wiersza na napisy, które mają być dopasowywane, a filtr zamienia je na małe litery, scala i szuka podciągu:

```ts
const globalFilterFn = useMemo(
  () =>
    createCatalogTableGlobalFilterFn<ProductCategory["adminListItem"]>((row) => {
      const statusLabel = t(row.status === CATEGORY_STATUS.ACTIVE ? CATEGORY_STATUS_LABEL_KEYS.active : CATEGORY_STATUS_LABEL_KEYS.draft)

      return getCategoryAdminSearchParts(row, statusLabel)
    }),
  [t],
)
```

Przekazanie przetłumaczonej etykiety statusu oznacza, że w panelu po polsku można szukać frazy „aktywna”, a po angielsku „active”, w tych samych wierszach.

### Przeciąganie wierszy

Tabele z możliwością zmiany kolejności zawsze przekazują `RowReorderApi`, ale jego flaga `enabled` jest prawdą tylko wtedy, gdy widoczna jest naturalna kolejność — przeciąganie wierszy przy aktywnym sortowaniu albo filtrze nie miałoby sensu:

```ts
const columnFilters = table.atoms.columnFilters.get()
const sorting = table.atoms.sorting.get()
const search = String(table.atoms.globalFilter.get() ?? "").trim()
const naturalOrder = sorting.length === 0 && columnFilters.length === 0 && search === ""
const rowReorder = useMemo<RowReorderApi>(
  () => ({
    draggingId: ordering.draggingId,
    enabled: naturalOrder,
    onRowDragEnter: ordering.handleDragEnter,
    onRowDragStart: ordering.handleDragStart,
    onRowDrop: ordering.handleDrop,
    onRowMove: ordering.handleMove,
  }),
  [naturalOrder, ordering],
)
```

Handlery przeciągania pochodzą z hooka `use-<entity>-ordering.ts`, który utrzymuje optymistyczną lokalną kolejność i zapisuje ją przez mutację zmieniającą kolejność. Hook tabeli łączy jedno z drugim: `const reorder = useReorderCategories()` tworzy mutację, a `useCategoryOrdering(categories, reorder)` zwraca `items` przekazywane do `useDataGridInstance` jako `data` oraz powyższe handlery. Tabele bez zmiany kolejności przekazują `rowReorder: undefined`.

## 4. Złóż tabelę

Rozpakuj komponenty tabeli raz, na końcu pliku, i rozłóż je wewnątrz `DataGridShell`:

```tsx
const { Body, Export, Pagination, Provider, Toolbar } = categoriesDataGrid
```

```tsx
<Provider value={grid}>
  <div className={ADMIN_CATALOG_DATAGRID_PAGE_CLASS}>
    <CategoriesStats />
    <DataGridShell>
      <Toolbar actions={toolbarActions}>
        <CategoriesRefreshAction />
        <Export />
        <CategoriesStatusFilter />
      </Toolbar>
      <Body />
      <Pagination />
    </DataGridShell>
  </div>
</Provider>
```

`DataGridShell` to karta z `grid-rows-[auto_minmax(0,1fr)_auto]`, więc pasek narzędzi i stronicowanie zachowują wysokość, a treść się przewija. Pierwszy rząd paska narzędzi zawsze zawiera pole wyszukiwania, menu widoczności kolumn i przycisk resetu układu, a po nich slot `children` (kontrolki w linii). Slot `actions` stoi w tym samym rzędzie, wyrównany do prawej, a slot `filters`, jeśli zostanie przekazany, dostaje własny rząd poniżej. Przycisk resetu wywołuje `resetPreferences` i pozostaje wyłączony, dopóki `hasPreferenceOverrides` nie jest prawdą.

Komponent tabeli jest też właścicielem panelu tworzenia i edycji. `hooks/use-categories-sheet.tsx` eksportuje `useCategoriesSheetState` (zwykły `useState` z `mode` — `"closed"`, `"create"` albo `"edit"` — i wybranym wierszem), `CategoriesSheetProvider` oraz `useCategoriesSheet`. Komponent trasy tworzy stan i owija stronę w dostawcę; `CategoriesTableContent` przekazuje `sheet.openEdit` do hooka tabeli jako `onRowClick`, przycisk dodawania na pasku narzędzi wywołuje `openCreate`, menu wiersza wywołuje `openEdit`, a `CategorySheet` jest montowany tylko wtedy, gdy `sheet.open` jest prawdą.

## 5. Pozwól wyeksportować tabelę

Menu **Eksportuj** na pasku narzędzi pobiera tabelę jako CSV, JSON, XML albo zwykły tekst. Plik zawiera kolumny, które administrator widzi, w kolejności, w jakiej je widzi, pod nagłówkami, które czyta, oraz wszystkie wiersze wybrane bieżącymi filtrami i wyszukiwaniem — a nie tylko widoczną stronę. Tabela wczytywana w całości eksportuje wiersze w kolejności, którą pokazuje jej sortowanie. Tabela stronicowana na serwerze — dziennik zdarzeń, zamówienia, klienci i subskrybenci newslettera — eksportuje w kolejności serwera, bo sortowanie po nagłówku zmienia tam tylko kolejność widocznej strony; tabela produktów wysyła swoje sortowanie na serwer i eksportuje w tej kolejności.

Kolumna trafia do eksportu, gdy jej `meta` ma `exportValue`: funkcję, która z wiersza robi tekst widoczny w komórce, albo zwraca `undefined` dla pustej komórki. Zapisuj to, co widzi administrator — przetłumaczone etykiety, ceny przez `formatPrice` w formacie administratora, daty przez `useFormatter` — bo plik nie przechowuje surowych wartości. Kolumny bez tej funkcji, takie jak `select`, `drag`, `image` i `actions`, nigdy nie są eksportowane, a kolumna, której nagłówek nie jest zwykłym tekstem, trafiłaby do pliku pod swoim identyfikatorem, więc kolumna do eksportu potrzebuje przetłumaczonego `header`. Z `.../audit/lib/audit-column-defs.tsx`:

```tsx
columnHelper.accessor("detail", {
  cell: ({ getValue }) => <AuditDetailCell detail={getValue()} />,
  header: t("audit.columns.detail"),
  id: AUDIT_LOG_TABLE_COLUMN_ID.detail,
  meta: {
    exportValue: (row) => (row.detail === undefined ? undefined : formatAuditLogDetail(row.detail, { locale: formatLocale, t })),
    skeletonVariant: "text",
  },
  size: AUDIT_LOG_TABLE_COLUMN_SIZE.detail,
})
```

`exportValue` ma typ wiersza danej tabeli: `data-grid.types.ts` deklaruje go na interfejsie `ColumnMeta` z TanStack, który zna typ wiersza i rozszerza `DataGridColumnMeta` o pozostałe opcje.

Następnie hook tabeli mówi, co jest eksportowane, dodając `exportSource` do wartości kontekstu:

| Pole       | Znaczenie                                                                                                                                                                          |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `list`     | Stała nazwa do nazwy pliku i metadanych, na przykład `audit-log`                                                                                                                   |
| `title`    | Tytuł strony w języku strony                                                                                                                                                       |
| `filters`  | Aktywne filtry opisane słowami, jako `{ label, value }`. `exportFilter(label, value)` pomija filtr, który nie jest ustawiony, a `describeDateFilter` opisuje filtr daty            |
| `loadRows` | Dla tabeli stronicowanej na serwerze wczytuje wszystkie wiersze przez serwerową funkcję eksportu listy, z filtrami, wyszukiwaniem i sortowaniem zapytania o stronę, ale bez strony |
| `search`   | Dla źródła z `loadRows` wyszukiwanie, które wysłało na serwer — wartość po odczekaniu, a nie tekst wciąż wpisywany w pole wyszukiwania                                             |

Wyszukiwanie eksport dodaje do filtrów sam: `search` źródła z `loadRows` albo pole wyszukiwania tabeli wczytywanej w całości. Taka tabela pomija `loadRows`, a eksport bierze wiersze, które trzyma po zastosowaniu filtrów i sortowania, ze wszystkich stron. Lista zbyt długa na jedno żądanie do Workera wczytuje eksport stronami: `loadRows` dziennika zdarzeń prosi `exportAuditLogs` o kolejne strony po `LIST_PAGE_SIZE_MAX` wpisów, dopóki strona nie wróci niepełna, a każda strona po pierwszej czyta tylko wpisy zapisane przed chwilą ustaloną przez pierwszą stronę, więc wpisy dodane w międzyczasie nie przesuwają stron. Skrót z `.../audit/hooks/use-audit-export-source.ts`:

```ts
const loadAuditLogPages = async (input: AuditExportInput, page: number, until?: number): Promise<AuditLog["adminListItem"][]> => {
  const result = await exportAuditLogs({ data: { ...input, page, until } })

  return result.hasMore ? [...result.items, ...(await loadAuditLogPages(input, page + LIST_PAGE_STEP, result.until))] : result.items
}

return useMemo(
  () => ({
    filters: [
      ...exportFilter(t("audit.columns.category"), input.category === undefined ? undefined : t(`audit.categories.${input.category}`)),
      ...exportFilter(t("audit.columns.status"), input.severity === undefined ? undefined : t(`audit.severity.${input.severity}`)),
    ],
    list: AUDIT_LOG_EXPORT_LIST,
    loadRows: () => loadAuditLogPages(input, LIST_PAGE_FIRST),
    search: input.search,
    title: t("audit.title"),
  }),
  [input, t],
)
```

Serwerowa funkcja eksportu leży obok listy, w `use-cases/export-<entity>.ts`. Jest zabezpieczona tak samo jak lista, przyjmuje dane wejściowe listy bez `page` i `pageSize`, zwraca wiersze w postaci elementów listy i zapisuje eksport przez `recordListExportedAudit` z wpisem dla listy w `LIST_EXPORT_AUDIT_EVENTS` oraz akcją `*_LIST_EXPORTED` z etykietami w obu językach.

Na koniec wstaw `<Export />` na pasek narzędzi, obok przycisku odświeżania. `Export` rzuca błąd, gdy wartość kontekstu nie ma `exportSource`, więc tabela, której nie należy eksportować, po prostu pomija ten komponent.

Serializatory to zwykłe funkcje w `src/presentation/components/custom/datagrid/lib/table-export.ts`, testowane w jego katalogu `__test__/`:

- **CSV**: znacznik kolejności bajtów UTF-8, żeby Excel poprawnie odczytał polskie litery, końce wierszy CRLF i cytowanie według RFC 4180. Pola rozdziela średnik, gdy format administratora zapisuje ułamki przecinkiem, jak polski, żeby dwukrotnie kliknięty plik otworzył się w polskim Excelu w kolumnach, a w przeciwnym razie przecinek; pole zawierające separator jest cytowane. Wartość zaczynająca się od `=`, `+`, `-`, `@`, tabulatora albo powrotu karetki dostaje na początku `'`, więc arkusz ją pokazuje, zamiast wykonywać jako formułę.
- **JSON**: sformatowany, z obiektem `metadata` (`list`, `title`, `exportedAt` w ISO UTC, `timeZone`, `rowCount`, `filters`, `columns`) i `rows` z kluczami według identyfikatorów kolumn.
- **XML**: XML 1.0 z korzeniem `<export>`, w którym są `<metadata>` i `<rows>`, a w nich jeden `<row>` na wiersz z elementem na każdą kolumnę; pięć znaków specjalnych jest zamienianych na encje, a znaki niedozwolone w XML 1.0 są usuwane.
- **TXT**: nagłówek z tytułem, czasem eksportu i strefą czasową, liczbą wierszy i filtrami, a potem jeden rekord na wiersz jako linie `Kolumna: wartość`, rozdzielone pustą linią.

Pliki mają nazwy `<list>-<RRRR-MM-DD-GGmm>.<rozszerzenie>` według zegara administratora i są zapisywane przez `downloadTextFile` z `src/presentation/components/custom/datagrid/lib/download.ts`. Teksty menu leżą pod `export` w przestrzeni `components.datagrid`.

## 6. Dodaj akcje wiersza i akcje zbiorcze

Każda tabela ma dwa komponenty obok siebie:

- `<entity>-row-actions.tsx` — menu dla jednego wiersza, renderowane przez kolumnę `actions` z `meta.preventRowClick`, żeby otwarcie menu nie otwierało jednocześnie panelu edycji.
- `<entity>-bulk-actions.tsx` — czyta `table.getFilteredSelectedRowModel().rows` z `categoriesDataGrid.useDataGrid()` i działa na zaznaczeniu; renderowane w slocie `actions` paska narzędzi.

Oba wywołują `use-delete-<entity>.ts`, hook będący właścicielem mutacji usuwania, jej powiadomień i unieważniania cache'u. Mutacja zmiany kolejności, `use-reorder-<entity>.ts`, jest podłączana w hooku tabeli — zobacz wyżej Przeciąganie wierszy.

## 7. Stronicowanie po stronie serwera, jeśli tabela jest duża

Kategorie, kolekcje i atrybuty są ładowane w całości przez `useSuspenseQuery` i filtrowane, sortowane oraz stronicowane w przeglądarce. Zamówienia, klienci, kupony, subskrybenci newslettera i dziennik zdarzeń są stronicowane na serwerze: hook tabeli trzyma `pagination` i filtry w stanie React, buduje z nich zapytanie o stronę przez `useQuery({ ...pageQuery, placeholderData: keepPreviousData })` i przekazuje bieżącą stronę do `useDataGridInstance`. Najmniejszym przykładem jest `.../admin/coupons/hooks/use-coupons-data-grid.ts`:

```ts
const { columnReorder, hasPreferenceOverrides, resetPreferences, table } = useDataGridInstance({
  columns,
  data: [...data.items],
  defaultColumnVisibility: ADMIN_DISCOUNT_TABLE_DEFAULT_COLUMN_VISIBILITY,
  defaultPageSize: ADMIN_DISCOUNTS_PAGE_SIZE,
  getRowId: (row) => row.id,
  initialColumnOrder,
  initialColumnPinning: ADMIN_DISCOUNT_TABLE_COLUMN_PINNING,
  manualPagination: true,
  onPaginationChange: setPagination,
  pageCount: Math.ceil(data.total / pagination.pageSize),
  pagination,
  persistenceKey: couponsDataGrid.persistenceKey,
  rowCount: data.total,
})
```

`useDataGridInstance` ma trzy przełączniki dla danych z serwera — `manualPagination`, `manualFiltering` i `manualSorting` — oraz kontrolowany stan, którego wymagają: `pagination` z `onPaginationChange`, `sorting` z `onSortingChange`, `pageCount`, `rowCount` i `onColumnFiltersChange`, żeby kopiować filtry kolumn do parametrów zapytania. Kupony i subskrybenci ustawiają tylko `manualPagination`; zamówienia, klienci i dziennik zdarzeń dokładają `manualFiltering`; tylko tabela produktów ustawia `manualSorting`.

Tabela produktów (`src/routes/admin.catalog.products.index.tsx`) jest hybrydą. Bez wyszukiwania, filtra paska narzędzi i filtra kolumny ładuje wszystkie produkty przez `getAdminProductsQuery()` i działa w przeglądarce, dzięki czemu przeciąganie wierszy pozostaje dostępne. Gdy tylko któryś z nich zostanie ustawiony (`hasProductsServerListQuery`), `use-products-list-data.ts` przełącza się na zapytanie o stronę, a trzy flagi `manual*` idą za tym:

```ts
const pageQueryOptions = getAdminProductsPageQuery({
  categoryId: filters.categoryId,
  collectionId: filters.collectionId,
  createdAt: columnFilters.createdAt,
  inventoryLevel: filters.inventoryLevel,
  minPrice: columnFilters.minPrice,
  page: pagination.pageIndex + LIST_PAGE_STEP,
  pageSize: pagination.pageSize,
  search,
  sort,
  status: filters.status,
  totalStock: columnFilters.totalStock,
  variantKind: filters.variantKind,
})
```

`LIST_PAGE_STEP` z `src/modules/_core/utils/pagination.ts` to przeliczenie z numeracji od zera na numerację od jedynki. `placeholderData: keepPreviousData` utrzymuje poprzednią stronę na ekranie, dopóki nie doładuje się następna. Każda zmiana zbioru wyników musi wracać na pierwszą stronę — bez tego filtr zastosowany na siódmej stronie pokazałby pustą tabelę. Tabela kuponów resetuje `pageIndex` do zera w efekcie wyszukiwania i w `applyCouponsFilter`, które czyści też zaznaczenie wierszy. W tabeli produktów `use-products-server-list-sync.ts` resetuje go, gdy nadejdzie niepuste opóźnione wyszukiwanie, a w trybie serwerowym także przy każdej zmianie filtrów kolumn albo sortowania; czyści też sortowanie serwerowe, gdy tabela wraca do trybu przeglądarki.

Wyszukiwania po stronie serwera są opóźniane przed dotarciem do zapytania: `use-admin-debounced-table-search.ts` czyta globalny filtr tabeli i opóźnia go o 300 ms przez `src/hooks/use-debounce.ts`. Samo pole wyszukiwania zapisuje globalny filtr przy każdym naciśnięciu klawisza, co w zupełności wystarcza tabeli działającej w przeglądarce.

### Filtry dat w strefie czasowej administratora

Filtr daty wybiera dni kalendarzowe, a dzień zaczyna się o północy w strefie czasowej wyświetlania administratora, nie w UTC. Wspólnym okienkiem jest `AdminDateColumnFilter` z `src/presentation/components/custom/pages/admin/lib/admin-date-column-filter.tsx`. Zapisuje w wartości filtra kolumny `{ operator, date }` albo `{ operator: "between", startDate, endDate }` z datami ISO; operatory to `on`, `before`, `after` i `between`. Wybrane dni opisuje, a „dzisiaj” wyznacza przez `useAdminDateFilterDay()`, które korzysta z `useFormatter()` i `useDisplayTimeZone()`. Każda tabela owija go własnymi przetłumaczonymi etykietami, jak robią to `products-created-at-column-filter.tsx` i `orders-date-column-filter.tsx`.

- **Przy filtrowaniu w przeglądarce** kolumna dopasowuje wiersze przez `filterFn: matchesDateColumnFilterIn(timeZone)` z `datagrid/lib/data-grid-date-filter.ts`, z `timeZone` z `useDisplayTimeZone()` przekazanym do budownika kolumn (tak robią kolumny produktów i klientów).
- **Przy filtrowaniu na serwerze** wartość filtra trafia do parametrów zapytania o stronę, a funkcja serwerowa sama ustala strefę czasową. Z `src/modules/product/use-cases/get-admin-products-page.ts`:

```ts
const { timeZone } = await resolveRequestDisplayPreferences()
const params = buildAdminProductsListParams(data, timeZone)
```

Akcesor zamienia potem filtr na SQL przez `buildAdminDateTimeFilterSql(column, filter, timeZone)` z `src/modules/_core/utils/datetime-column-filter.server.ts`, jak w `product.accessors.ts`:

```ts
if (params.createdAt !== undefined) {
  conditions.push(buildAdminDateTimeFilterSql(product.createdAt, params.createdAt, params.timeZone))
}
```

Przeglądarka nigdy nie wysyła strefy czasowej razem z filtrem. `resolveRequestDisplayPreferences()` z `src/integrations/use-intl/i18n.display-preferences.ts` zwraca te same preferencje, z którymi renderuje się strona — zapisane przez administratora, a w ich braku wykryte z żądania. Przypadki użycia list zamówień, klientów i dziennika zdarzeń działają tak samo. W testach podmień ten moduł na `src/platform/testing/mocks/display-preferences.ts` (`pl-PL`, `Europe/Warsaw`), jak robi to `list-audit-logs-query.test.ts`.

## 8. Przetestuj

Hooki i komponenty tabeli mają testy w `datagrid/**/__test__/`, a każda tabela panelu ma własne w swoim katalogu funkcjonalności. Testy tabel działają w projekcie Vitest `component` (`*.component.test.tsx`), który używa `jsdom` i `src/platform/testing/setup.ts` — ten plik podstawia `ResizeObserver` i `IntersectionObserver`, których tabela potrzebuje do mierzenia kolumn. Zobacz [Pisanie testów](/docs/guides/writing-tests).
